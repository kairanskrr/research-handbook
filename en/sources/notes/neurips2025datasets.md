# NeurIPS 2025: Call for Datasets & Benchmarks Track Papers

- Source: `neurips2025datasets`, [web page](https://neurips.cc/Conferences/2025/CallForDatasetsBenchmarks)
- Version: the NeurIPS 2025 Datasets and Benchmarks Track call for papers, read on 2026-10-17.
- Note: in 2025 the track's call follows the main conference call and adds three points: single-blind review is allowed, datasets and code must be provided at submission, and the track has its own scope. For reviewing factors and other content see `neurips2024datasets`.

### E1

- Location: DB track specifics, 2. Required dataset and benchmark code submission, Access
- Quote: "Datasets and code should be available and accessible to all reviewers, ACs and SACs at the time of submission. Data should be found and obtained without a personal request to the PI. Code should be documented and executable. Non-compliance justifies the desk rejection of the paper."
- Key point: Data and code must be accessible to reviewers at submission without a personal request to the PI, and code must be documented and executable; failing this justifies desk rejection.

### E2

- Location: DB track specifics, 2. Required dataset and benchmark code submission, Hosting
- Quote: "New datasets should be hosted at one of the hosting sites dedicated to ML datasets (Dataverse, Kaggle, Hugging Face, or OpenML) or at a bespoke hosting site if the dataset requires it."
- Key point: New datasets should be hosted on a dedicated machine learning data platform (Dataverse, Kaggle, Hugging Face, or OpenML), or on a bespoke site if the dataset requires it.

### E3

- Location: DB track specifics, 2. Required dataset and benchmark code submission, Metadata
- Quote: "Authors should use the Croissant machine-readable format to document their datasets in a machine-readable way and include the Croissant file with their paper submission in OpenReview."
- Key point: Datasets must be documented in Croissant, a machine-readable dataset description format, and the Croissant file submitted with the paper.

### E4

- Location: DB track specifics, 3. Specific scope
- Quote: "Advanced practices in data collection and curation that are of general interest even if the data itself cannot be shared. Private data sets, however, cannot be listed as contributions, and the methodology should also be validated on reproducible and publicly available data/tools."
- Key point: When data cannot be shared, the data collection and curation practices can be a contribution, but a private dataset cannot itself count as one, and the method must also be validated on reproducible, public data or tools.

### E5

- Location: DB track specifics, 2. Required dataset and benchmark code submission
- Quote: "All accepted papers should have their code and datasets documented and publicly available by the camera-ready deadline."
- Key point: Accepted papers must have their code and datasets documented and public by the camera-ready deadline.

### E6

- Location: DB track specifics, 3. Specific scope
- Quote: "Frameworks for responsible dataset development, audits of existing datasets, identifying significant problems with existing datasets and their use"
- Key point: The scope includes frameworks for responsible dataset development, audits of existing datasets, and identifying significant problems with existing datasets and their use.
