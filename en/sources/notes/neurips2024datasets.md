# NeurIPS 2024: Call for Datasets and Benchmarks Track Papers

- Source: `neurips2024datasets`, [web page](https://neurips.cc/Conferences/2024/CallForDatasetsBenchmarks)
- Version: the NeurIPS 2024 Datasets and Benchmarks Track call for papers, read on 2026-10-17.
- Note: a track that this top machine learning conference set up specifically for dataset and benchmark papers. The page covers submission requirements and the factors reviewers consider. Requirements change from year to year, so check that year's page; for the 2025 changes see `neurips2025datasets`.

### E1

- Location: Opening paragraph
- Quote: "On the other hand, they do require additional specific checks, such as a proper description of how the data was collected, whether they show intrinsic bias, and whether they will remain accessible."
- Key point: Datasets need specific checks: a proper description of how the data were collected, whether they carry intrinsic bias, and whether they will remain accessible.

### E2

- Location: CRITERIA
- Quote: "A key criterion is accessibility: datasets should be available and accessible, i.e. the data can be found and obtained without a personal request to the PI, and any required code should be open source."
- Key point: A key criterion is accessibility: the data can be found and obtained without a personal request to the PI, and any required code is open source.

### E3

- Location: SUBMISSION INSTRUCTIONS
- Quote: "Dataset documentation and intended uses. Recommended documentation frameworks include datasheets for datasets, dataset nutrition labels, data statements for NLP, data cards, and accountability frameworks." / "Hosting, licensing, and maintenance plan."
- Key point: Supplementary material for a new dataset must include documentation and intended uses (documentation frameworks such as datasheets are recommended) and a hosting, licensing, and maintenance plan.

### E4

- Location: SUBMISSION INSTRUCTIONS
- Quote: "Long-term preservation: It must be clear that the dataset will be available for a long time, either by uploading to a data repository or by explaining how the authors themselves will ensure this" / "Explicit license: Authors must choose a license, ideally a CC license for datasets, or an open source license for code"
- Key point: Authors must show the dataset will stay available long term, by uploading it to a data repository or explaining how they will ensure it, and must choose a license, ideally a Creative Commons (CC) license for data and an open source license for code.

### E5

- Location: SUBMISSION INSTRUCTIONS
- Quote: "Highly recommended: a persistent dereferenceable identifier (e.g. a DOI minted by a data repository or a prefix on identifiers.org) for datasets"
- Key point: A persistent, resolvable identifier for the dataset, such as a DOI from a data repository, is highly recommended.

### E6

- Location: SUBMISSION INSTRUCTIONS
- Quote: "For benchmarks, the supplementary materials must ensure that all results are easily reproducible."
- Key point: For benchmarks, the supplementary material must make all results easily reproducible.

### E7

- Location: REVIEWING AND SELECTION PROCESS, All submissions
- Quote: "Utility and quality of the submission: Impact, originality, novelty, relevance to the NeurIPS community will all be considered."
- Key point: Reviewers weigh utility and quality: impact, originality, novelty, and relevance to the community.

### E8

- Location: REVIEWING AND SELECTION PROCESS, Dataset submissions
- Quote: "Sufficient detail must be provided on how the data was collected and organized, what kind of information it contains" [...] "and how it will be made available and maintained."
- Key point: Documentation must be complete, with enough detail on how the data were collected and organized, what information they contain, and how they will be made available and maintained.

### E9

- Location: REVIEWING AND SELECTION PROCESS, Dataset submissions
- Quote: "Licensing and access: Per NeurIPS ethics guidelines, authors should provide licenses for any datasets released. These should consider the intended use and limitations of the dataset, and develop licenses and terms of use to prevent misuse or inappropriate use."
- Key point: Released datasets need licenses, and the license and terms of use should reflect intended uses and limitations to prevent misuse.

### E10

- Location: REVIEWING AND SELECTION PROCESS, Dataset submissions
- Quote: "datasets should minimize the exposure of any personally identifiable information, unless informed consent from those individuals is provided to do so. Any paper that chooses to create a dataset with real data of real people should ask for the explicit consent of participants, or explain why they were unable to do so."
- Key point: Datasets should minimize exposure of personally identifiable information; building a dataset from real people's data requires their explicit consent or an explanation of why it could not be obtained.

### E11

- Location: REVIEWING AND SELECTION PROCESS, Dataset submissions
- Quote: "Note that, if your submission includes publicly available datasets (e.g. as part of a larger benchmark), you should also check these datasets for ethical issues. You remain responsible for the ethical implications of including existing datasets or other data sources in your work."
- Key point: If you include public datasets in your benchmark, check them for ethical issues too; you remain responsible for the ethical consequences of the data you include.

### E12

- Location: FREQUENTLY ASKED QUESTIONS, credentialized access
- Quote: "This will be possible on the condition that a credentialization is necessary for the public good (e.g. because of ethically sensitive medical data)" / "This should be seen as an exceptional measure, and NOT as a way to limit access to data for other reasons"
- Key point: Requiring users to obtain credentials before access is allowed only when the public good requires it (for example, ethically sensitive medical data); it is an exception, not a way to restrict access.

### E13

- Location: FREQUENTLY ASKED QUESTIONS, Where should I submit it?
- Quote: "If the main contribution is a new dataset, benchmark, or other work that falls into the scope of the track (see above), then it is ideally reviewed accordingly." / "the reviewing procedures of the main conference are focused on algorithmic advances, analysis, and applications, while the reviewing in this track is equally stringent but designed to properly assess datasets and benchmarks."
- Key point: If the main contribution is a new dataset or benchmark, this track is the right venue: the main conference reviews for algorithms, analysis, and applications, while this track is equally stringent but built to assess datasets and benchmarks.

### E14

- Location: Opening paragraph
- Quote: "For instance, datasets can often not be reviewed in a double-blind fashion, and hence full anonymization will not be required."
- Key point: Datasets often cannot be reviewed double-blind, so full anonymization is not required.

### E15

- Location: REVIEWING AND SELECTION PROCESS, Dataset submissions
- Quote: "Legal compliance: For datasets, authors should ensure awareness and compliance with regional legal requirements."
- Key point: Authors must be aware of and comply with the legal requirements for data in their region.
