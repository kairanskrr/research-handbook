# Fox et al. 2021: Data and Software Sharing Guidance for Authors Submitting to AGU Journals

- Source: `fox2021agudata`, [Original](https://data.agu.org/resources/agu-data-software-sharing-guidance)
- Version: Guidance web page on the AGU open science site (CC BY 4.0), corresponding to the Zenodo record https://doi.org/10.5281/zenodo.5124741 . AGU's main "Data and Software for Authors" page returned 403 to scripts, and the Internet Archive snapshot loads its text by script and could not be read, so this note uses only this guidance. Locations are given as subheadings.

### E1

- Location: Introduction
- Quote: "These digital objects need to be accessible, understandable, and open as possible for reuse to support transparency and replicability."
- Key point: AGU journals require data and software to be as accessible, understandable, and open for reuse as possible, to support transparency and replicability. The list covers field observation data, satellite data, laboratory data, software used for analysis and modeling, and all data shown in the paper's figures.

### E2

- Location: Introduction
- Quote: "Data or software should be as open as possible, as closed as necessary. For data concerning Indigenous Peoples, authors should consult the CARE Principles for Indigenous Data Governance."
- Key point: Data and software should be "as open as possible, as closed as necessary"; for data concerning Indigenous Peoples, consult the CARE Principles.

### E3

- Location: 1. When to Make Your Data and Software Available
- Quote: "At the time your paper is submitted, your data and software must be available to the editors and reviewers."
- Key point: At submission, data and software must already be available to editors and reviewers.

### E4

- Location: 1. When to Make Your Data and Software Available
- Quote: "Data or software that are sensitive and require restrictions on access (e.g., personal data, medical information, fossil locations, strategic models) must be preserved in a repository with appropriate access controls."
- Key point: Sensitive data (for example, personal data or fossil locations) must still be preserved, in a repository with appropriate access controls.

### E5

- Location: Software Availability Statement (required)
- Quote: "Note that “git/GitHub/GitLab” are not acceptable software preservation repositories because they are not archival."
- Key point: GitHub and GitLab are not acceptable software preservation repositories because they are not archival.

### E6

- Location: 6. Availability Statements and Template Examples
- Quote: "Statements to the effect of “data available from authors” are not acceptable. Also, statements to the effect of “data available from http://nasa.gov” are not acceptable since high-level website references do not meet the AGU’s Data and Software for Authors requirements."
- Key point: Statements like "data available from authors," or ones that point only to the home page of a large website, do not meet AGU journal requirements.

### E7

- Location: 2. Guidelines for Research Primarily Based on Numerical Models or Theory
- Quote: "The goal is to provide sufficient information and resources so that an interested user, with sufficient computer resources, can replicate your simulation."
- Key point: Provide model configurations, parameters, and run scripts in enough detail that a reader with sufficient computing resources can replicate your simulation.

### E8

- Location: 2. Guidelines for Research Primarily Based on Numerical Models or Theory
- Quote: "There are currently limited resources for preserving files of very large size. However, selecting adequate output to produce manuscript figures and tables is generally much more manageable and is sufficient to meet the needs of replicability."
- Key point: Very large model output is hard to preserve in full, but preserving enough output to reproduce the paper's figures and tables is generally manageable and sufficient.

### E9

- Location: 3. Selecting a repository
- Quote: "Selecting a repository and determining data and software management best practices begins when you propose and fund your research project, through your Data (and Software) Management Plan."
- Key point: Choosing a repository and data management practices starts when you write the project proposal and the Data (and Software) Management Plan.

### E10

- Location: 1. Considerations for publication, Large Data
- Quote: "Large Data (>1TB): Preservation of large data may be possible in some repositories for a fee. Authors should account for this in their research budget and Data Management Plan."
- Key point: Preserving large data (over 1 TB) may cost a fee, which should go into the budget and the Data Management Plan.

### E11

- Location: 3. Selecting a repository, Institutional Repository
- Quote: "Librarians can be an excellent source of research data management support, including repository selection"
- Key point: Librarians can help with choosing a repository and with research data management.

### E12

- Location: 1. Considerations for publication, Data Citation
- Quote: "Include data citations for the primary and processed research data in the References section of your paper. Doing so ensures proper credit is given for the data."
- Key point: Cite both the primary and the processed data in the references, so that those who contributed the data get proper credit.

### E13

- Location: 2. Guidelines for Research Primarily Based on Numerical Models or Theory
- Quote: "In the Ocean modeling community it is common to use numerical models that are open access and well documented"
- Key point: In the ocean modeling community it is common to use numerical models that are open access and well documented (the guidance's description of this one area).

### E14

- Location: Software Availability Statement (required)
- Quote: "A Software Availability Statement is required in the Open Research section of your paper for software that is central to your research such as for model simulations, data analysis, data visualization, and model output analysis."
- Key point: AGU journals require a Software Availability Statement in the Open Research section, covering software for simulations, data analysis, visualization, and model output analysis.

### E15

- Location: 2. Guidelines for Research Primarily Based on Numerical Models or Theory
- Quote: "the software code (e.g. Python, Jupyter Notebooks, R, MATLAB) used to perform any data analysis and to produce the manuscript’s figures should be made available in a free and open platform (e.g., Github) and preserved in a repository (e.g., Zenodo)."
- Key point: Code used for data analysis and for making the figures should be made available on an open platform and preserved in a repository such as Zenodo.

### E16

- Location: Introduction
- Quote: "These digital objects include: [...] Data from observations collected in the field;"
- Key point: The digital objects AGU journals require to be shared include data from field observations.

### E17

- Location: 6. Availability Statements and Template Examples
- Quote: "Statements to the effect of “data available from authors” are not acceptable."
- Key point: A statement such as "data available from authors" does not meet AGU journal requirements.
