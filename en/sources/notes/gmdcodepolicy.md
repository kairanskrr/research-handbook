# Geoscientific Model Development: Code and data policy

- Source: `gmdcodepolicy`, [Original](https://www.geoscientific-model-development.net/policies/code_and_data_policy.html)
- Version: Code and data policy page of Geoscientific Model Development (GMD, an open-access journal of the European Geosciences Union, published by Copernicus), accessed 2026-10-06. Locations are given as subheadings.

### E1

- Location: Core principles
- Quote: "Every paper must include a section at the end of the paper before the "Acknowledgements" entitled "Code and data availability"."
- Key point: Every GMD paper must include a "Code and data availability" section before the Acknowledgements.

### E2

- Location: Core principles
- Quote: "This section must include citations for the persistent public archives of the precise versions of all of the code and data associated with the paper."
- Key point: This section must cite persistent public archives of the **precise versions** of all code and data used in the paper.

### E3

- Location: Core principles
- Quote: "They must also provide confidential access to the code and data for the editor and reviewers in order to enable peer review." / "All manuscripts which do not make code and data available at this level are to be rejected."
- Key point: Code and data that cannot be made public for reasons beyond the authors' control must still be provided confidentially to the editor and reviewers; manuscripts that do not do this are rejected.

### E4

- Location: Core principles
- Quote: "Code and data access must be provided at the time that the preprint is submitted. Embargoes, whether pending acceptance or for a defined period, are not acceptable."
- Key point: Code and data must be provided when the preprint is submitted; embargoes, whether until acceptance or for a set period, are not accepted.

### E5

- Location: Scope
- Quote: "preprocessing, run control and postprocessing scripts covering every data processing action for all the results reported in the paper"
- Key point: The required materials include preprocessing, run control, and postprocessing scripts covering every data processing step.

### E6

- Location: Archive standards
- Quote: "Project or institution websites and online revision control sites such as GitHub, GitLab or Bitbucket are made for code development but not suitable for archiving frozen code versions."
- Key point: Project websites and code hosting sites such as GitHub are made for development, not for archiving frozen code versions.

### E7

- Location: Archive standards
- Quote: "Where code and data change during the revision process of the manuscript, the updated versions must also be archived."
- Key point: If code and data change during revision, the updated versions must also be archived and match the revised manuscript's results.

### E8

- Location: Scope
- Quote: "During the review process, the ease of model download, compilation, and running of test cases may be assessed."
- Key point: During review, how easy it is to download and compile the model and run test cases may be assessed.

### E9

- Location: Useful additions from Copernicus Publications' data policy
- Quote: "Video supplements, video abstracts, International Geo Sample Numbers, and other digital assets should be linked to the article through DOIs in the assets tab."
- Key point: Copernicus journals let authors link digital assets such as International Geo Sample Numbers (IGSN) to the article through DOIs in the assets tab.

### E10

- Location: Useful additions from Copernicus Publications' data policy
- Quote: "With Earth System Science Data (ESSD) Copernicus Publications provides a journal dedicated to the publication of data papers, including peer review of data sets."
- Key point: Copernicus publishes Earth System Science Data (ESSD), a journal dedicated to data papers, including peer review of datasets.
