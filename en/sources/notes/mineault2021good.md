# Mineault 2021: The Good Research Code Handbook

- Source: `mineault2021good`, [Setting up your project](https://goodresearch.dev/setup), [Document your code](https://goodresearch.dev/docs)
- Version: the author's online handbook, web pages read 2026-10-05. Locations give the page and subheading.

### E1

- Location: Setting up your project, Pick a name and create a folder for your project
- Quote: "As an academic, a project will tend to naturally map to a paper. Therefore, one project = one paper = one folder = one git repository is a generally a good default structure."
- Key point: In academia a project usually maps to a paper; "one project = one paper = one folder = one git repository" is a good default structure.

### E2

- Location: same as above
- Quote: "You might want to create extra standalone projects for tools you re-use across different papers."
- Key point: Tools you reuse across papers can get their own standalone projects.

### E3

- Location: Setting up your project, Initialize a git repository and sync to Github
- Quote: "Depending on your pace, you should aim to commit your code from a few times a day to a few times per week. Don’t wait until the project is almost finished before you start to commit. [...] The general rule of thumb is that one commit should represent a unit of related work."
- Key point: Commit your code from a few times a day to a few times a week, not just when the project is almost finished; each commit should cover one related piece of work.

- Key point: Documentation is a love letter that you write to your future self.
