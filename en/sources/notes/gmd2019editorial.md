# GMD Executive Editors 2019: Editorial: The publication of geoscientific model developments v1.2

- Source: `gmd2019editorial`, [Original](https://doi.org/10.5194/gmd-12-2215-2019)
- Version: Geoscientific Model Development 12, 2215–2225, 2019, open access (CC BY 4.0). Read from the PDF on the journal website.

### E1

- Location: Abstract
- Quote: "Best practice in code and data archiving continues to develop and is far from universal among scientists."
- Key point: The editors of Geoscientific Model Development (GMD) find that best practice in code and data archiving is still far from universal among scientists.

### E2

- Location: §2
- Quote: "Bugs occur in essentially all non-trivial code."
- Key point: Bugs occur in essentially all non-trivial code.

### E3

- Location: §2
- Quote: "Even given two codes attempting to implement the same algorithm, there is no guarantee that the results will be the same, and without source code it is impossible to establish the underlying cause of the differences."
- Key point: Two programs implementing the same algorithm may not give the same results, and without source code it is impossible to find the cause of the differences.

### E4

- Location: §3.1 Source code is necessary but not sufficient
- Quote: "It is also necessary to have access to all of the input data and to know all of the steps which were taken from raw data to points on graphs or numbers in tables."
- Key point: Source code alone is not enough; you also need all the input data and every step taken from raw data to each point on a graph and each number in a table.

### E5

- Location: §3.2 Manual processing considered harmful
- Quote: "This frequently occurs when figures are produced interactively. Unfortunately, this breaks the provenance chain between the model and the paper" / "The only remedy for this is for authors to consistently ensure that there is no manual processing of the data: models are run by a script, and all pre- and post-processing is scripted."
- Key point: Producing figures or processing data interactively by hand breaks the provenance chain between the model and the paper; the only remedy is to run and process everything by script.

### E6

- Location: §3.3 Source code or data may be unavailable
- Quote: "In particular, some of the current Earth system models have restricted licences controlled by large institutions."
- Key point: Some Earth system models have restrictive licenses controlled by large institutions, so their code cannot be freely released.

### E7

- Location: §3.4 Embargoes
- Quote: "It is the opinion of the GMD editors that if the code is not ready, then neither is the manuscript."
- Key point: The GMD editors' view: if the code is not ready, neither is the manuscript.

### E8

- Location: §4 Journals and archives
- Quote: "if code has not been curated sufficiently well, it may not be possible to recover the exact version used in a paper"
- Key point: If code has not been curated well, it may be impossible to recover the exact version used in a paper later, so "available from the authors" is not reliable.

### E9

- Location: §3.5 Archive on submission
- Quote: "at the core of the open review process of European Geosciences Union journals is the idea that the submitted manuscript and the review process are openly and persistently available to scrutiny."
- Key point: European Geosciences Union (EGU) journals use open review: the submitted manuscript and the review process are openly and persistently available.

### E10

- Location: §3.5 Archive on submission
- Quote: "the code and data availability section in the manuscript can and should identify the preferred download location for the latest model version, in addition to citing the archived version corresponding to the given publication."
- Key point: Cite the archived version corresponding to the paper and also give the download location for the latest version; the two go together.
