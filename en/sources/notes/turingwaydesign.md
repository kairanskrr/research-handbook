# The Turing Way: Guide for Project Design

- Source: `turingwaydesign`, [Overview of Project Design](https://book.the-turing-way.org/project-design/pd-overview), [Getting Started Checklist](https://book.the-turing-way.org/project-design/pd-overview/pd-checklist), [Project Management Methodologies](https://book.the-turing-way.org/project-design/project-management-methodologies/overview)
- Version: The Turing Way, an open handbook written by its community (CC-BY 4.0), web pages, accessed 2026-10-05. Locations give the page and subheading.

### E1

- Location: Overview of Project Design, Learning from Mistakes (project design regrets researchers looked back on)
- Quote: "Not advocating for clearer goals and success criteria from the beginning."
- Key point: The first regret researchers named: not advocating for clearer goals and success criteria from the beginning.

### E2

- Location: Same as above
- Quote: "Not setting short- and long-term milestones"
- Key point: One regret: not setting short- and long-term milestones.

### E3

- Location: Same as above
- Quote: "Trying to plan too much at the beginning and never getting started."
- Key point: An opposite regret: trying to plan too much at the beginning and never getting started.

### E4

- Location: Same as above
- Quote: "Not properly taking into account the degree to which requirements will change throughout a project - which happens a lot in academia - and the effect this has on designs that then also need to change."
- Key point: Not properly accounting for how much requirements change over a project (which happens a lot in academia), and that designs then need to change too.

### E5

- Location: Getting Started Checklist, Timeline & Milestones
- Quote: "Establish a project timeline with key milestones, output, and deadlines. [...] Break down the project into manageable phases or tasks. [...] Useful documentation: Gantt charts, roadmaps, or project boards."
- Key point: Set up a project timeline with key milestones, outputs, and deadlines; break the project into manageable phases or tasks; Gantt charts, roadmaps, and project boards are useful documentation.

### E6

- Location: Getting Started Checklist, Aims & Values
- Quote: "Define the main research questions and objectives."
- Key point: At the start of a project, define the main research questions and objectives.

### E7

- Location: Project Management Methodologies, Summary
- Quote: "Research projects are often characterised by uncertainty, evolving objectives, and a need for flexibility."
- Key point: Research projects are often characterized by uncertainty, evolving objectives, and a need for flexibility.

### E8

- Location: Project Management Methodologies, the Waterfall row of the comparison table
- Quote: "Less suitable for research due to its rigid structure and difficulty in accommodating changes once the process has begun."
- Key point: Waterfall project management (carrying out steps in a fixed sequence) is less suitable for research because its structure is rigid and it is hard to accommodate changes once the process has begun.
