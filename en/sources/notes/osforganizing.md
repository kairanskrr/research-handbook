# OSF Support: Organizing files

- Source: `osforganizing`, [original](https://help.osf.io/article/147-organizing-files)
- Version: Official help documentation for the OSF platform from the Center for Open Science, web page, read 2026-10-05. Locations give subheadings.

### E1

- Location: Organizing files
- Quote: "Organizing your files using names and locations that are informative help to document what your files are and how they relate to other files. The more informative your file organization, the more reproducible your research will be."
- Key point: File names and locations are themselves documentation; the more informative your file organization, the more reproducible your research.

### E2

- Location: Separate raw data from derived data
- Quote: "Within your data/ component, create separate subdirectories for raw data, derived data, and data summaries."
- Key point: Within the data directory, keep raw data, derived data, and data summaries in separate subdirectories.

### E3

- Location: Make raw data read-only
- Quote: "When you are not entering data, make your raw data file read-only to ensure it is not altered or mixed with other data. [...] Don’t attempt calculations, sums, or visualizations within the raw data file."
- Key point: Make raw data files read-only when you are not entering data, and do not do calculations, sums, or visualizations inside the raw data file.

### E4

- Location: Make README files
- Quote: "Document the files contents and purpose of the directory and each subdirectory. [...] Whenever files are added or the subdirectory is changed, update the README file to document the changes."
- Key point: Use a README to document the contents and purpose of the directory and each subdirectory; update it whenever files are added or the directory changes.
