# Scientific Data: Submission Guidelines (for Data Descriptor papers)

- Source: `scientificdata2026guidelines`, [web page](https://www.nature.com/sdata/submission-guidelines)
- Version: the Scientific Data submission guidelines page, read on 2026-10-17.
- Note: Scientific Data is a Nature open-access journal devoted to describing datasets, covering the natural sciences, medicine, the social sciences, and other fields. Only the requirements for the Data Descriptor article type are excerpted here.

### E1

- Location: 1. Select an article type, Format outline (Data Descriptor)
- Quote: "Background & Summary" / "Methods" / "Data Records" / "Data Overview (optional)" / "Technical Validation" / "Usage Notes (optional)" / "Data Availability" / "Code Availability"
- Key point: A Data Descriptor is structured as Background & Summary, Methods, Data Records, Data Overview (optional), Technical Validation, Usage Notes (optional), Data Availability, and Code Availability.

### E2

- Location: 3. Prepare the manuscript, Background & Summary
- Quote: "For Data Descriptors, this section should provide an overview of dataset, including the motivation for creating it, as well as outlining the potential reuse value where applicable." / "Please do not include subjective claims on novelty, impact, or utility."
- Key point: The background gives an overview of the dataset, why it was created, and how others might reuse it, without subjective claims about novelty, impact, or utility.

### E3

- Location: 3. Prepare the manuscript, Methods
- Quote: "Methods in Data Descriptors should describe the steps or procedures used to create the data, including full descriptions of the experimental design, data acquisition and any computational processing."
- Key point: The Methods section describes the steps that produced the data, with full descriptions of experimental design, data acquisition, and all computational processing.

### E4

- Location: 3. Prepare the manuscript, Methods
- Quote: "Where continuously updated input data have been used, authors should provide the version number or search terms used to create it at a level of detail that allows others to find the same input and repeat the work."
- Key point: When continuously updated input data are used, give the version number or search terms in enough detail that others can find the same input and repeat the work.

### E5

- Location: 3. Prepare the manuscript, Data Record
- Quote: "This section should be used to explain what the dataset contains, including the repository where the dataset is hosted, an overview of the data files and their formats, and any folder structure." / "The section should also define any column headings, variable names, or other fields/metadata if you believe these would not be understood to users"
- Key point: The Data Records section explains what the dataset contains: the hosting repository, the files and their formats, the folder structure, and definitions of any column headings or variable names users might not understand.

### E6

- Location: 3. Prepare the manuscript, Data Overview
- Quote: "Data Descriptors should not contain results, discussion, or analyses. This is because the fundamental goal of a Data Descriptor is to describe the technical contents of a dataset to encourage others to use it, without bias."
- Key point: Data Descriptors contain no results, discussion, or analyses, because their basic purpose is to describe a dataset's technical contents without bias and encourage others to use it.

### E7

- Location: 3. Prepare the manuscript, Technical Validation
- Quote: "This section should describe the experiments, analyses or checks needed to support the technical quality of the dataset, with any supporting figures and tables, as needed."
- Key point: The Technical Validation section describes the experiments, analyses, or checks that support the technical quality of the dataset.

### E8

- Location: 2. Deposit the dataset
- Quote: "For first round review we require that data are available for download and review by reviewers via any URL that allows anonymous download." / "From the second round of review onwards we require that data are public and available in a formal data repository that meets our policy, in preparation for any final publication."
- Key point: In the first round of review, data must be anonymously downloadable by reviewers; from the second round on, data must be public in a formal data repository that meets the journal's policy.

### E9

- Location: 3. Prepare the manuscript, Usage Notes
- Quote: "'Usage Notes' is an optional section that can be used to provide information that may assist other researchers who reuse your data. Most commonly these are additional technical notes about how to access or process the data."
- Key point: Usage Notes is an optional section to help people reuse the data, most often technical notes on how to access or process it.

### E10

- Location: 1. Select an article type, Scope (Data Descriptor)
- Quote: "Descriptions of datasets shared in repositories" / "Peer-reviewed?" / "Yes"
- Key point: The scope of a Data Descriptor is describing datasets shared in repositories, and the table marks it as peer reviewed.
