# 核心术语

这本手册反复用到几个词。它们在日常说话里经常混用，但在做研究时，分清它们能帮你少走很多弯路。本页把它们一次讲清楚，全书都按这里的意思使用。

例子都取自同一个方向："大模型与智能合约安全"。

---

## 一条链：从方向到证据

一个研究项目，大致是沿着下面这条链逐步变清楚的：

```
方向 → 问题 → 研究问题 → 主张 → 证据
```

主张一旦清楚，你要交出的贡献、该走的研究套路、该用的方法，也就跟着清楚了。

这不是一条走一遍就结束的直线。后面的环节常常会把你送回前面：发现证据拿不到，就要改问题；发现只能证明很弱的主张，就要回头换个角度。怎么在这条链上来回调整，见[收敛成项目](../01_find-a-problem/05_converge.md)。

## 方向

**你感兴趣、或导师交给你的一片领域。** 例如"用大模型做智能合约安全"。

方向还不能直接动手做。它没有告诉你要解决什么、做到什么程度算完。新手最常见的状态，就是手里只有一个方向。

## 问题

**这片领域里，有什么不对劲、不够好、或者还不知道的地方。** 例如：

- 现有的漏洞检测工具误报太多，开发者不愿意用；
- 大家都说大模型检测漏洞很准，但没人确认评测数据有没有被模型"见过"。

问题回答的是"为什么值得做"。说不出问题，只有方向，研究就没有着力点。

## 研究问题

**把问题收窄成一个能被回答的问句。** 例如："现有大模型漏洞检测的评测结果，有多少来自评测集的数据泄露？"

好的研究问题有明确的边界：研究什么对象、在什么条件下、回答到什么程度。"大模型能不能用于智能合约安全？"这样的问句太宽，答案只能是"在某些情况下能"，等于没回答。

## 主张

**你希望读者读完论文后相信的那句话。** 它是研究问题的答案，也是整篇论文要证明的东西。例如："现有评测结果中，约一半的准确率来自数据泄露。"

主张要用表示**结果**的说法，而不是表示**活动**的说法[^shaw2003writing-e18]。"我们研究了 X"描述的是你做了什么，"X 在条件 Y 下能达到 Z"描述的是你发现了什么。前者读者不知道该相信什么，后者才是主张。

一篇论文通常有一条核心主张，加上几条支撑它的次要主张。

## 贡献

**这个研究给领域增加了什么新东西。** 可以是一个新方法、一个新数据集、一项新发现、一个新评测集、一个证明……

贡献和主张关系密切，但不是一回事：贡献是你**交出的东西**，主张是你**关于它说的话**。例如贡献是"一个去除了泄露的新评测集"，主张是"在新评测集上，现有工具的准确率下降了一半"。

## 证据

**让一个持怀疑态度的读者相信你的主张所需要的东西。** 可以是实验结果、测量数据、访谈材料、证明、对文献的系统分析……

要问的是：读者凭什么相信你？应该用什么标准衡量你的主张？什么具体证据能表明你的结果满足了主张[^shaw2003writing-e6]？

证据由主张决定，而不是反过来。先有"我要证明什么"，再决定"要拿出什么"。

## 研究套路

**这个项目主要靠什么逻辑产生新知识。** 同一个方向可以走不同的套路，套路不同，要做的事就完全不同：

| 套路 | 产生的知识 | 例子 |
|---|---|---|
| 观察描述 | 现象是什么样的 | "大模型生成的合约中，四成有重入漏洞" |
| 测量 | 某个东西怎么测才准 | "现有评测集存在数据泄露，新评测集更可靠" |
| 比较评估 | 已有做法中哪个更好 | "在真实合约上，工具 A 的检出率高于 B" |
| 解释因果 | 为什么会这样 | "提供漏洞模式提示会提高检出率" |
| 构建改进 | 一个更好的东西 | "新方法多发现三成漏洞" |
| 综合 | 已有知识的整体图景 | "该方向的研究可归为四类，存在三个空白" |
| 证明 | 形式上必然成立的结论 | "在条件 C 下，该算法一定终止" |
| 解读论证 | 对文本、制度、思想的新理解 | 多见于人文社科 |

一个项目常常同时有几类贡献，例如既提出新方法、又发布数据集。这时按**核心主张**属于哪一类来定主要套路，其他作为次要部分。

为什么要分清套路：问题、结果和验证方式要互相匹配[^shaw2002makes-e9]，而且没有一套适用于所有研究的质量标准，每项研究都要按适合它的标准来评价[^ralph2020empirical-e24]。用"构建改进"的标准去要求一项"观察描述"的研究（比如要求它和基线比较），就是用错了标准。

## 研究方法

**具体怎么收集和分析证据的做法。** 例如对照实验、问卷调查、访谈、仓库挖掘、基准评测、形式化证明。

套路和方法是两层东西。套路说"要产生什么知识"，方法说"用什么手段拿到证据"。一种方法可以服务于不同的套路：对照实验既可以用来比较两个工具（比较评估），也可以用来检验某个因素是否导致了某个结果（解释因果）。

## 学科规矩

**某个研究社区特有的惯例和要求。** 例如计算机以会议论文为主、很多会议要求提交可复现的研究制品；心理学研究要过伦理审批、常要求预注册。

这些规矩不改变研究的基本逻辑，但决定了"在这个社区里，什么样的证据才会被接受"。

## 一个例子：同一个方向，四种不同的研究

方向都是"大模型与智能合约安全"，核心主张不同，研究就完全不同：

| 核心主张 | 套路 | 要做的事 |
|---|---|---|
| "新方法比现有工具多发现三成漏洞，误报更少" | 构建改进 | 实现方法，选评测集和基线，做对比和消融实验 |
| "大模型生成的合约中，四成有重入漏洞" | 观察描述 | 收集大量生成的合约，系统地分析漏洞分布 |
| "提供漏洞模式提示会提高检出率" | 解释因果 | 只改变提示方式、其他条件不变，做对照实验 |
| "现有评测集有严重泄露，结果被高估" | 测量 | 证明泄露存在，展示修正后结论怎么变化 |

所以，拿到一个方向时，第一个要想清楚的问题不是"用什么方法"，而是"**我最后要证明哪句话**"。
