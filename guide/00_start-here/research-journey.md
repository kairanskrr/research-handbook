# 全程地图：从兴趣到发表

> **状态**：初稿，待审阅 · **最后更新**：2026-10-07
>
> 本页的道理适用于各学科，例子和具体做法以计算机为例。

你可能刚拿到一个方向，比如导师说"去看看大模型和智能合约安全"；也可能已经在做实验，却说不清自己做到了哪一步、离发表还有多远。

这一页是整本手册的地图：一个研究从模糊的兴趣走到发表，要经过哪几章，每章交出什么，走到什么程度可以往下，什么时候要往回走。具体做法都在各章里，这里只给路线。手册怎么读、每章按什么结构写，见[怎么用这本手册](how-to-use.md)；文中的方向、问题、主张、证据、研究套路等词，意思见[核心术语](key-concepts.md)。

读完这一页，你应该能说出自己现在在哪一章、手里缺哪样东西、下一步该读什么。

---

## 1. 一张图看全程

```
  主线一            主线二              主线三          主线四
  从兴趣到项目  →  从项目到研究设计  →  执行和分析  →  写作和发表
  想清楚做什么      想清楚怎么证明       拿到证据         讲给别人听
       ↑                 ↑                  │                │
       └─────────────────┴── 结果、审稿意见常常把你送回前面 ──┘

  随时查阅：研究套路 · 研究方法 · 学科篇 · 贯穿全程 · 常见问题速查
```

主线四个阶段按顺序读；下面一行是参考层，用到时再查，见[怎么用这本手册](how-to-use.md#手册分成两部分主线和参考层)。

| 阶段 | 要回答的问题 | 走完时手里有 |
|---|---|---|
| 主线一：从兴趣到项目 | 做什么？值得做吗？做得出来吗？ | 一页项目简介、研究计划 |
| 主线二：从项目到研究设计 | 要拿出什么证据？用什么方法拿？结论可能错在哪？ | 证据清单、证据—方法表、威胁处理表、试过的设计 |
| 主线三：执行和分析 | 证据拿到了吗？它说明了什么？ | 可追溯的结果、按证据更新过的主张 |
| 主线四：写作和发表 | 怎么讲清楚？投到哪里？怎么回应审稿人？ | 论文、投稿材料、回复与修改稿 |

## 2. 每一章：交出什么，做到什么可以往下

下面每张表，"交出什么"取自各章的"产出物"，"至少要做到"是各章"检查点"里最关键的一两条。完整清单以各章为准 `[本项目分析]`。

### 主线一：从兴趣到项目

| 章节 | 交出什么 | 往下走之前，至少要做到 |
|---|---|---|
| [进入领域、探索文献](../01_from-interest-to-project/01_enter-a-field.md) | 核心论文清单、每篇的笔记、问题记录、领域地图 | 能几句话讲清方向分哪几块；问题记录里有十来条注明出处的疑问 |
| [找到候选问题](../01_from-interest-to-project/02_find-problems.md) | 十条左右的想法清单，初筛留下两到四条 | 每条留下的候选都说得出"不对劲在哪"，并想好一两周内能做的小尝试 |
| [收敛成项目](../01_from-interest-to-project/03_converge.md)（核心章） | 一页项目简介、最接近工作的对比表、空的结果表、一个做过的小实验 | 一句话说出核心结论；最没把握的部分试过，没有否定整个想法；导师没有根本性的反对 |
| [形成研究计划](../01_from-interest-to-project/04_research-plan.md) | 一两页的研究计划、论文提纲 | 每个里程碑写成"拿到了什么证据"；排第一的是最可能让项目失败的那个；留了余量 |

这一阶段最关键的是收敛：把"我对 X 感兴趣"变成"我要证明这句话"。核心主张定下来，后面的套路、证据和方法才跟着定，例子见[核心术语](key-concepts.md#一个例子同一个方向四种不同的研究)。

## 3. 一条产出物的链

每一章的产出，都是下一章的输入。用这条链检查自己走到了哪里，比用"做了几个月"检查更准 `[本项目分析]`：

```
一页项目简介 → 研究计划 → 证据清单 → 研究设计 → 结果 → 论文 → 回复与修改稿
```

其中"研究设计"指证据—方法表、威胁处理表，以及试验后改过的设计；"结果"指能追溯的运行记录和结论与证据对照表。

这些产出物不是做完一个就扔一个。一页简介和计划要一直更新；结果出来后，常常要回头改它们 `[本项目分析]`。

**这条链也要倒着用。** 项目一开始就想着最终的论文：在最初的设计文档里放一份论文提纲，用它来确定研究目标和实验的逻辑顺序[^zhang2014ten-e8]。收敛时画空的结果表、做计划时写论文提纲，都是这个做法，具体见[形成研究计划](../01_from-interest-to-project/04_research-plan.md#2-把主张拆成里程碑每个里程碑是一份证据)。

## 4. 研究是循环：什么时候往回走

第 1 节的图画成一条直线，实际走起来不是。实验会反过来让你修改论文草稿[^eisnerfirst-e8]；发现事情比想象的复杂，退回前面的阶段是完全正常的，不代表你搞砸了[^nanda2025process-e6]。关键是知道**回到哪里**。下表汇总了各章"回退信号"里最常见的几种：

| 你在哪一章 | 出现这种情况 | 回到哪里 |
|---|---|---|
| 找到候选问题 | 想了几周，一条想法都写不出来 | [进入领域、探索文献](../01_from-interest-to-project/01_enter-a-field.md)，再读一批 |
| 收敛成项目 | 对领域了解太少，判断不了重要性和新颖性 | [进入领域、探索文献](../01_from-interest-to-project/01_enter-a-field.md)，针对这个问题再读 |
| 收敛成项目 | 所有候选结论都被证明别人做过了 | [找到候选问题](../01_from-interest-to-project/02_find-problems.md) |
| 收敛成项目 | 小实验否定了核心假设 | 留在本章，回到[第 1 节](../01_from-interest-to-project/03_converge.md#1-写出你想证明的那句话)换一个候选结论 |
| 形成研究计划 | 倒推后发现，再怎么收窄主张时间也不够 | [收敛成项目](../01_from-interest-to-project/03_converge.md#1-写出你想证明的那句话)第 1 节，换一个更小的结论，或和导师商量换去处 |
| 从研究问题到证据清单 | 写"否定"标准时发现，怎样的结果你都能解释成支持 | [收敛成项目](../01_from-interest-to-project/03_converge.md#1-写出你想证明的那句话)第 1 节，主张可能太含糊或太满 |
| 选定研究套路和方法 | 某条证据用哪种方法都拿不到 | [从研究问题到证据清单](../02_from-project-to-study/01_question-to-evidence.md)，换一条能拿到的证据 |
| 效度与局限 | 有一个会让主张作废的威胁，怎么也消除不了 | [收敛成项目](../01_from-interest-to-project/03_converge.md#1-写出你想证明的那句话)第 1 节，把主张改小或换一个 |
| 先做小规模试验 | 核心假设不成立，比如要测的差别几乎不存在 | [收敛成项目](../01_from-interest-to-project/03_converge.md#1-写出你想证明的那句话)，收窄或换一个主张 |
| 执行与迭代 | 某个关键部分被证明做不成，而它当初没有试过 | [先做小规模试验，排除最大风险](../02_from-project-to-study/04_pilot-and-derisk.md)，把剩下的风险先试一遍 |
| 执行与迭代 | 改动多到原来的计划已经对不上 | [形成研究计划](../01_from-interest-to-project/04_research-plan.md#7-计划怎样改)第 7 节，从主张开始重改计划 |
| 分析与解读 | 有一个致命的其他解释，现有设计排除不了 | [效度与局限](../02_from-project-to-study/03_validity-and-limits.md)，补设计 |
| 分析与解读 | 探索中发现了一个更有意思的问题 | [收敛成项目](../01_from-interest-to-project/03_converge.md)，把它当成新的候选，和导师商量 |
| 讲清故事，写成论文 | 写作中发现缺一个关键实验，主张站不住 | [执行与迭代](../03_conduct-and-analyze/01_run-and-iterate.md)，补实验 |
| 选择发表渠道与投稿 | 读了目标去处的论文，发现你的证据明显不够 | [执行与迭代](../03_conduct-and-analyze/01_run-and-iterate.md)补实验，或收窄主张 |
| 审稿意见、修改与被拒之后 | 审稿人认可问题，但认为证据撑不住结论 | [效度与局限](../02_from-project-to-study/03_validity-and-limits.md)，或[从研究问题到证据清单](../02_from-project-to-study/01_question-to-evidence.md) |
| 审稿意见、修改与被拒之后 | 审稿人一致认为早有人做过，或贡献不够 | [收敛成项目](../01_from-interest-to-project/03_converge.md#3-别人做过了吗)第 3 节 |

表里可以看出，最常被退回的地方是[收敛成项目](../01_from-interest-to-project/03_converge.md)：主张没想清楚，问题往往要到后面才暴露 `[本项目分析]`。写作这一行尤其常见：提前排出整篇论文，几乎总会暴露出几个必须补做的关键实验[^karpathy2016survival-e9]，这也是要尽早动笔的原因。

**往回走之前，先写一句"为什么回去、回去要回答什么"，并更新一页简介。** 这样回退是有目标的，而不是推倒重来 `[本项目分析]`。

**也不要来回乱跳。** 不看好的方向要果断放下，但总在换方向、哪一个都没好好探索，就什么也学不到[^nanda2025mindsets-e1]。什么时候该坚持、什么时候该换，见[执行与迭代](../03_conduct-and-analyze/01_run-and-iterate.md#6-坚持还是换方向)。

**新手最常见的一种卡住**，是以为自己该有明确的假设了，其实还在探索[^nanda2025process-e2]。怎样分辨这两个阶段、各自该做什么，见[执行与迭代](../03_conduct-and-analyze/01_run-and-iterate.md#1-先认清自己在哪个阶段)。

## 5. 先做最可能失败的部分

不论在哪一章排工作顺序，都优先做最可能失败、又能很快得到答案的部分：失败时浪费更少，也能更快得到信息[^steinhardt2018stochastic-e3]。这条原则在主线上出现了三次 `[本项目分析]`：

- 收敛时，用一个最便宜的小实验先试最没把握的部分，见[收敛成项目](../01_from-interest-to-project/03_converge.md#5-你做得出来吗)；
- 做计划时，把"它不行、整个项目就不成立"的里程碑排在第一，见[形成研究计划](../01_from-interest-to-project/04_research-plan.md#4-排顺序最可能失败的先做)；
- 设计好后、正式执行前，先小规模试验，见[先做小规模试验，排除最大风险](../02_from-project-to-study/04_pilot-and-derisk.md)。

## 6. 参考层和贯穿全程的事

参考层（研究套路、研究方法、学科篇、常见问题速查）各讲什么、什么时候查，见[怎么用这本手册](how-to-use.md#手册分成两部分主线和参考层)。这里只补两点。

**研究套路从读文献一直用到写论文**，不只在选方法时才用，见[为什么从头到尾都要想着套路](../05_research-strategies/README.md#为什么从头到尾都要想着套路)。

**学科规矩会改变节奏，但不改变主线。** 例如计算机可能是唯一一个以会议为主要发表渠道的学科[^vardi2009conferences-e1]，所以计算机的项目常常按会议截止日期倒推；四个阶段还是那四个，只是终点的形式和时间不同 `[本项目分析]`。见[计算机领域概况](../fields/computer-science/README.md#一篇会议论文的一生)。

[贯穿全程](../08_throughout/README.md)的几页不属于哪一章，但有两件事最好从第一天就开始 `[本项目分析]`：

- **和导师对齐。** 每一章的产出物（简介、计划、设计、结果、草稿）都给导师看，见[合作与导师](../08_throughout/collaboration_and_advisors.md)。
- **让每个结果都能找回来源。** 最低要求是一年后你自己还能大致重现[^sandve2013ten-e2]；等到写论文、回复审稿意见时再补，往往已经补不回来了。见[整理科研材料](../08_throughout/organizing_materials.md)。

诚信与伦理问题（比如要不要伦理审批、署名怎么定）也最好在设计时就想到，见[科研诚信与伦理](../08_throughout/integrity_and_ethics.md)。

## 7. 大概要花多久

**一个项目从开始到发表要多久，本文资料没有给出通用的数字。** 它取决于研究套路、学科的发表方式，以及中间往回走了几次 `[本项目分析]`。与其记一个数字，不如学会估：从投稿截止日期倒推、测出自己的估时偏差、为往回走留余量，做法见[形成研究计划](../01_from-interest-to-project/04_research-plan.md#5-估时间并把余量留出来)；每天、每周怎么安排，见[计划与日常节奏](../08_throughout/planning_and_routines.md)。

投稿之后还有一段时间不在你手里：审稿要等，被拒要改投。这段时间各学科、各去处差别很大，流程见[选择发表渠道与投稿](../04_write-and-publish/02_venue-and-submission.md#6-投出去之后会发生什么)。

如果你在后面的章节，却发现前面的产出物缺了（比如在做实验，却写不出一页简介），先回去补上。缺的那一样，往往就是你现在卡住的原因 `[本项目分析]`。

遇到具体困难，例如实验一直做不出来、被拒稿、和导师沟通不顺，也可以先查[常见问题速查](../faq.md)。
