# 怎么用这本手册

> **状态**：初稿，待审阅 · **最后更新**：2026-10-07

## 这本手册写给谁

你可能是第一次做研究的学生：导师给了一个方向，或者你自己对某个话题感兴趣，但不知道从哪里下手、每一步该做到什么程度。你也可能已经做过一两个项目，现在卡在某一步，想找个能照着走的办法。

这本手册就是写给你的。它不讲某个学科的专业知识，讲的是**怎么把一个研究从模糊的想法做到发表**：每个阶段要想清楚什么、做出什么、怎样判断能不能往下走。

读之前，建议先花十分钟看两页：

- [全程地图](research-journey.md)：一个研究从头到尾要经过哪几个阶段，哪里会来回走；
- [核心术语](key-concepts.md)：方向、问题、研究问题、主张、贡献、证据、研究套路、研究方法、学科规矩。全书都按那一页的意思用这些词。

---

## 手册分成两部分：主线和参考层

**主线**按研究的先后顺序写，告诉你**现在该决定什么**。一共四个阶段，按顺序读：

| 阶段 | 你要走到哪里 |
|---|---|
| 1. [从兴趣到项目](../01_from-interest-to-project/01_enter-a-field.md) | 从一个方向出发，读文献、找问题，收敛成一个站得住的项目，再定出研究计划 |
| 2. [从项目到研究设计](../02_from-project-to-study/01_question-to-evidence.md) | 把要证明的话变成要拿的证据，选好研究套路和方法，想清楚结论能说到哪里，先做小规模试验 |
| 3. [执行和分析](../03_conduct-and-analyze/01_run-and-iterate.md) | 把研究做出来，边做边调整，再分析结果、解释它说明了什么 |
| 4. [写作和发表](../04_write-and-publish/01_story-and-paper.md) | 把研究写成论文，选投稿的地方，应对审稿和修改 |

**参考层**不按顺序读，主线需要时会链接过去，你也可以直接查：

| 参考层 | 讲什么 | 什么时候来查 |
|---|---|---|
| [研究套路](../05_research-strategies/README.md) | 八种研究各产生什么知识、需要什么证据、常用哪些方法 | 你写出了核心主张，想知道自己做的是哪一种研究、审稿人会要什么证据 |
| 研究方法（目前放在各学科篇的"研究类型"下，例如[计算机篇](../07_fields/computer-science/README.md#研究类型)） | 一种具体做法怎么做好，比如[对照实验](../06_methods/controlled_experiment.md)、[访谈](../06_methods/interview_study.md)、[问卷](../06_methods/questionnaire_survey.md) | 你已经定了套路，要动手收集和分析证据 |
| [学科篇](../07_fields/README.md) | 某个学科、某个研究社区特有的规矩，比如发表文化、伦理审批 | 你要进入一个学科，或者想知道"在这个社区里什么证据才会被接受" |
| [贯穿全程](../08_throughout/README.md) | 不属于某个阶段、但一直要面对的事：计划和日常安排、材料整理、导师与合作、诚信和伦理、心态与成长、当审稿人 | 遇到这些事的时候 |
| [常见问题速查](../faq.md) | 按"遇到了什么情况"列出建议，链接到详细的段落 | 你有一个具体的麻烦，想直接找办法 |

**主线和参考层怎么配合：** 主线告诉你此刻要做什么决定，参考层告诉你做这个决定需要的细节。比如在[收敛成项目](../01_from-interest-to-project/03_converge.md)里，你写出了主张，判断它属于"构建改进"这种套路；这时去读[构建改进](../05_research-strategies/build_improve.md)，看这类研究要拿出什么证据；等到设计研究时，再去查具体方法怎么做。不需要先把参考层读完再开始。`[本项目分析]`

**写下来：** 用一句话写下你现在的处境，比如"导师给了方向，还没读论文"或"实验做了一半，结果和预想不一样"。下一节按这句话找你的读法。

## 按你的处境选读法

**第一次做研究，从零开始。**

1. 先读[全程地图](research-journey.md)和[核心术语](key-concepts.md)；
2. 从主线一的[进入领域、探索文献](../01_from-interest-to-project/01_enter-a-field.md)开始，按顺序往下读，每读一章就做那一章的练习；
3. 遇到研究套路、方法、学科规矩的链接，先跟过去看与你有关的部分，看完回到主线。

**已经在做项目，卡在某个阶段。**

1. 先翻[全程地图](research-journey.md)，找到你现在所在的阶段；
2. 直接读那一章，先看开头的"你现在在哪里"，确认说的是你的情况；
3. 再看那一章的"检查点"：前一阶段的检查点有没有真的满足？很多卡住的情况，问题其实出在前一步。例如实验做不下去，常常是因为当初要证明的那句话就没想清楚，这时要回到[收敛成项目](../01_from-interest-to-project/03_converge.md)。`[本项目分析]`

**需要某种具体方法。**

1. 如果已经知道要用什么方法，直接去方法页面；
2. 如果还不确定该用哪种方法，先读对应的[研究套路](../05_research-strategies/README.md)，除了还只是占位的"解读论证"，每篇套路都有一节"常用的研究方法"，告诉你这类研究一般用哪些方法；
3. 还拿不准自己属于哪种套路，读[研究套路](../05_research-strategies/README.md#怎样选出主要套路)里"怎样选出主要套路"一节。

**进入一个新的学科或方向。**

1. 先读主线一的[进入领域、探索文献](../01_from-interest-to-project/01_enter-a-field.md)：怎样找核心论文、关键的人和主要发表处；
2. 再读这个学科在[学科篇](../07_fields/README.md)里的概况，了解它的发表方式、伦理要求和常见做法；
3. 如果你从别的学科转过来，特别留意新学科里"什么样的证据才算够"和你原来学科的不同。

**遇到一个具体麻烦**（导师没空、实验一直不成、被拒稿……）：先查[常见问题速查](../faq.md)。

## 主线每一章都按同一个结构写

主线的每一章，都按下面的顺序展开：

| 部分 | 它帮你做什么 |
|---|---|
| 你现在在哪里 | 确认这一章说的是你的处境 |
| 这一阶段要解决什么 | 知道这一章结束时你该想清楚什么 |
| 怎么做 | 分小节讲做法，每节末尾有一个"**写下来：**"小练习 |
| 关键判断、常见错误 | 遇到岔路时怎么选，哪些坑别人常掉进去 |
| 产出物 | 这一阶段结束时，你手里应该有哪些东西 |
| 检查点 | 满足哪几条，就可以进入下一阶段 |
| 回退信号 | 出现什么情况，说明要退回哪一章 |
| 下一步 | 接下来读哪里 |

**"写下来"的练习一定要做。** 光读不写，你会觉得每一章都懂了，但真要回答导师"你到底要证明什么"时还是答不上来。练习的产出会一步步汇成你的项目材料：一页项目简介、相关工作对比表、研究计划……这些东西本身就是你和导师讨论的依据。`[本项目分析]`

**把检查点当成自查清单，而不是考试。** 不必每条都做到完美；但如果某一条你明显做不到，先别往下走，看看回退信号表，那里会告诉你该回哪里补。

**来回走是正常的。** 研究不是一条走一遍就结束的直线，后面的发现常常把你送回前面。回退信号就是为这种时候准备的：它不是失败的标志，而是告诉你回到哪里最省力。`[本项目分析]`

## 怎么看出处

手册里的话分两类，标法不同。

**有资料依据的话，挂脚注。** 某位作者的具体建议、某项研究的发现、某个规范的要求，句末都有一个脚注。例如：写你的贡献时，要用表示结果的动词，而不是"研究了""探索了"这类只表示做了事的动词[^shaw2003writing-e18]。点开脚注，能看到出自哪份资料、在原文的哪个位置；再点"证据"，能看到原文的那一两句话，不用找全文就能核对。证据摘录的格式见[证据摘录说明](../../sources/notes/README.md)。

**我们自己综合出来的建议，标 `[本项目分析]`。** 比如做法表格、判断规则、例子，是本手册根据多份资料归纳的，没有哪份资料逐字这样说。这类建议按段落（或整个小节、整张表格）标一次，不逐句标；但同一段里如果夹着数字、某项研究的发现这类事实，那句话仍然单独挂脚注。读到这类内容，可以把它当成一条有道理的建议，但要知道它不是某份资料的原话；和导师的意见不一致时，以你所在团队的具体情况为准。

另外两种你可能会遇到的情况：

- **"不同的看法"**：资料之间有分歧、而且分歧会影响你怎么做时，手册会把几种做法和各自的理由并列写出，由你结合自己的情况选。
- **"本文资料未涉及"**：手册找不到可靠依据的地方，会直接这样写，而不是凭印象给一个说法。

## 例子先用计算机

手册的结构按所有学科都能用的方式设计：四个阶段、八种研究套路、主张和证据的关系，我们认为在各学科都适用 `[本项目分析]`。但例子和具体做法目前先用计算机，主线各章和套路篇的开头都会注明这一点。

主线各章和多数套路篇反复用同一个例子："**大模型与智能合约安全**"。你会看到同一个方向在不同阶段怎样推进：怎样从这个方向里找出问题、写出要证明的那句话、选出研究套路、设计证据。这些例子是为了说明做法，不是一个真实项目的完整故事。

如果你不是学计算机的，主线的做法大多仍然适用，只是例子要换成你自己学科的 `[本项目分析]`；具体方法和学科规矩，以[学科篇](../07_fields/README.md)里你所在学科的内容为准。其他学科的例子和做法会陆续补充。

**写下来：** 把"大模型与智能合约安全"换成你自己的方向，写一句话。读主线时，每遇到一个例子，就试着用你的方向套一遍。
