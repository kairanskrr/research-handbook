# 怎么用这本手册

## 这本手册写给谁

你可能是第一次做研究的学生：导师给了一个方向，或者你自己对某个话题感兴趣，但不知道从哪里下手、每一步该做到什么程度。你也可能已经做过一两个项目，现在卡在某一步，想找个能照着走的办法。

这本手册就是写给你的。它不讲某个学科的专业知识，讲的是**怎么把一个研究从模糊的想法做到发表**：每个阶段要想清楚什么、做出什么、怎样判断能不能往下走。

不用从第一页读到最后一页。先在下一节的表里找到你现在的处境，从那一页开始读。

第一次做研究的话，先花十分钟看两页：[全程地图](research-journey.md)讲一个研究从头到尾要经过哪几步、哪里会来回走；[核心术语](key-concepts.md)讲方向、问题、研究问题、主张、贡献、证据、研究套路、研究方法、学科规矩这几个词，全书都按那一页的意思用。

几种处境的补充：

- **卡在某一章时**，先看那一章开头的"你现在在哪里"，确认说的是你的情况；再看前一章的"检查点"有没有真的满足。很多卡住的情况，问题其实出在前一步。例如实验做不下去，常常是因为当初要证明的那句话就没想清楚，这时要回到[收敛成项目](../01_find-a-problem/05_converge.md)。
- **还不确定该用哪种方法时**，先读对应的[研究套路](../05_research-strategies/README.md)：每篇套路都有一节"常用的研究方法"。还拿不准自己属于哪种套路，读其中[怎样选出主要套路](../05_research-strategies/README.md#怎样选出主要套路)一节。
- **从别的学科转过来时**，特别留意新学科里"什么样的证据才算够"和你原来学科的不同。

**写下来：** 用一句话写下你现在的处境，比如"导师给了方向，还没读论文"或"实验做了一半，结果和预想不一样"。然后在上表里找到对应的那一行。

## 手册的结构：两部分主干，加上参考

### 主干：两部分

手册的主干只有两部分，按研究的先后顺序写，告诉你**现在该决定什么**：

| 部分 | 它在做什么 | 走完时手里有 |
|---|---|---|
| **第一部分 · 想到一个好题目**：[1.1 进入领域](../01_find-a-problem/01_enter-a-field.md) · [1.2 生成候选问题](../01_find-a-problem/02_generate-problems.md) · [1.3 动手探索](../01_find-a-problem/03_explore.md) · [1.4 判断和筛选](../01_find-a-problem/04_judge-and-screen.md) · [1.5 收敛成项目](../01_find-a-problem/05_converge.md) | **探索**：读文献、攒想法、动手试、筛选，直到写得出一句要证明的话 | 一句写得下来、也知道拿什么证据检验的话；据此判断出研究类型 |
| **第二部分 · 把它做出来**：[2.1 证据清单](../02_do-the-project/01_question-to-evidence.md) · [2.2 选方法](../02_do-the-project/02_choose-method.md) · [2.3 研究计划](../02_do-the-project/03_research-plan.md) · [2.4 效度与局限](../02_do-the-project/04_validity-and-limits.md) · [2.5 小规模试验](../02_do-the-project/05_pilot-and-derisk.md) · [2.6 执行与迭代](../02_do-the-project/06_run-and-iterate.md) · [2.7 分析与解读](../02_do-the-project/07_analyze-and-interpret.md) · [2.8 决策点](../02_do-the-project/08_decision-points.md) | **验证**：把那句话变成要拿的证据，设计、试跑、执行、分析 | 填满的结果表，和每条结论都对得上证据的论文骨架 |

两部分的分界，是你能不能写下一个具体的假设，并说出什么证据能判断它。新手在项目早期卡住，常常是因为以为自己已经在检验阶段，其实还在探索阶段[^nanda2025process-e2]。

第二部分不是一条直线，而是围绕几个决策点的循环：试验、数据、分析都可能让你调整设计，甚至退回第一部分。做到后面发现事情比想象中乱，退回去是正常的，不代表你搞砸了[^nanda2025process-e6]。每个关键时刻怎么选，见[2.8 决策点](../02_do-the-project/08_decision-points.md)。

**写作和发表**单独成一部分：[讲清故事，写成论文](../03_write-and-publish/01_story-and-paper.md) · [选择发表渠道与投稿](../03_write-and-publish/02_venue-and-submission.md) · [审稿意见、修改与被拒之后](../03_write-and-publish/03_review-and-revision.md)。它排在后面，动笔却应该很早：一句主张、空的结果表、证据清单、填满的结果表、贡献清单，在两部分里一样接一样长出来，最后就是论文的骨架，见[2.8 一路维护的论文骨架](../02_do-the-project/08_decision-points.md#4-一路维护的论文骨架)。

参考部分不按顺序读，主干需要时会链接过去，你也可以直接查：

| 参考 | 讲什么 | 什么时候来查 |
|---|---|---|
| [研究类型](../06_methods/README.md) | 一种具体做法怎么做好，比如[对照实验](../06_methods/controlled_experiment.md)、[访谈](../06_methods/interview_study.md)、[问卷](../06_methods/questionnaire_survey.md)、[基准评测](../07_fields/computer-science/practices/benchmarking.md)。这个目录合并了多个学科都用的方法，和各学科独有的实践 | 第一部分出口判断出研究类型后；第二部分选方法、动手收集和分析证据时 |
| [学科篇](../07_fields/README.md) | 某个学科、某个研究社区特有的规矩，比如发表文化、伦理审批 | 你要进入一个学科，或者想知道"在这个社区里什么证据才会被接受" |

| [常见问题速查](../faq.md) | 按"遇到了什么情况"列出建议，链接到详细的段落 | 你有一个具体的麻烦，想直接找办法 |

**主干和参考怎么配合：** 主干告诉你此刻要做什么决定，参考告诉你做这个决定需要的细节。比如在[收敛成项目](../01_find-a-problem/05_converge.md)里，你写出了"现有大模型漏洞检测的评测结果被数据泄露高估了"，判断它属于"测量"这种套路；这时去读[测量](../05_research-strategies/measure.md)，看这类研究要拿出什么证据；等到第二部分选方法时，再去[研究类型](../06_methods/README.md)里查[基准评测](../07_fields/computer-science/practices/benchmarking.md)具体怎么做。不需要先把参考读完再开始。

## 每一章都按同一个结构写

两部分和写作发表的每一章，都按下面的顺序展开：

| 部分 | 它帮你做什么 |
|---|---|
| 你现在在哪里 | 确认这一章说的是你的处境 |
| 这一阶段要解决什么 | 知道这一章结束时你该想清楚什么 |
| 怎么做 | 分小节讲做法，每节末尾有一个"**写下来：**"小练习 |
| 关键判断、常见错误 | 遇到岔路时怎么选，哪些坑别人常掉进去 |
| 产出物 | 这一阶段结束时，你手里应该有哪些东西 |
| 检查点 | 满足哪几条，就可以进入下一阶段 |
| 回退信号 | 出现什么情况，说明要退回哪一章 |
| 下一步 | 接下来读哪里 |

**"写下来"的练习一定要做。** 光读不写，你会觉得每一章都懂了，但真要回答导师"你到底要证明什么"时还是答不上来。练习的产出会一步步汇成你的项目材料：领域地图、想法清单、探索笔记、一页项目简介、证据清单、研究计划……这些东西本身就是你和导师讨论的依据。

**把检查点当成自查清单，而不是考试。** 不必每条都做到完美；但如果某一条你明显做不到，先别往下走，看看回退信号表，那里会告诉你该回哪里补。

**来回走是正常的。** 研究不是一条走一遍就结束的直线，后面的发现常常把你送回前面。回退信号就是为这种时候准备的：它不是失败的标志，而是告诉你回到哪里最省力。

## 怎么看出处

手册里的话分两类，看有没有脚注就能分清。

**有资料依据的话，挂脚注。** 某位作者的具体建议、某项研究的发现、某个规范的要求，句末都有一个脚注。例如：写你的贡献时，要用表示结果的动词，而不是"研究了""探索了"这类只表示做了事的动词[^shaw2003writing-e18]。点开脚注，能看到出自哪份资料、在原文的哪个位置；再点"证据"，能看到原文的那一两句话，不用找全文就能核对。证据摘录的格式见[证据摘录说明](../../sources/notes/README.md)。

**没有脚注的话，是本手册自己的归纳和建议。** 比如做法表格、判断规则、例子，是本手册根据多份资料归纳的，没有哪份资料逐字这样说。这类内容不另加标记：句末有脚注的出自资料，没有脚注的就是我们的话。少数容易混淆的地方，例如紧跟在引文后面的推论，或者对某份资料本身的判断，正文会直接写明这是本手册的判断。读到这类内容，可以把它当成一条有道理的建议，但要知道它不是某份资料的原话；和导师的意见不一致时，以你所在团队的具体情况为准。

另外两种你可能会遇到的情况：

- **"不同的看法"**：资料之间有分歧、而且分歧会影响你怎么做时，手册会把几种做法和各自的理由并列写出，由你结合自己的情况选。
- **"本文资料未涉及"**：手册找不到可靠依据的地方，会直接这样写，而不是凭印象给一个说法。

## 例子先用计算机

手册的结构按所有学科都能用的方式设计：探索和验证两部分、八种研究套路、主张和证据的关系，我们认为在各学科都适用。但例子和具体做法目前先用计算机，各章和套路篇的开头都会注明这一点。

两部分各章和多数套路篇反复用同一个例子：方向是"**大模型与智能合约安全**"，核心主张是"**现有大模型漏洞检测的评测结果被数据泄露高估了**"，这是一个测量类的实证项目。各章的例子是这个项目的连续进展：上一章写出的东西，下一章接着用。你会看到同一个方向怎样找出问题、动手探索、写出要证明的那句话、列出证据、设计和试跑。这些例子是为了说明做法，不是一个真实项目的完整故事。

如果你不是学计算机的，两部分的做法大多仍然适用，只是例子要换成你自己学科的；具体方法和学科规矩，以[学科篇](../07_fields/README.md)里你所在学科的内容为准。其他学科的例子和做法会陆续补充。

**写下来：** 把"大模型与智能合约安全"换成你自己的方向，写一句话。读各章时，每遇到一个例子，就试着用你的方向套一遍。
