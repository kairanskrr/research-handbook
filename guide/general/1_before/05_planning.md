# 做计划：从终点倒推，按证据定里程碑

> **状态**：初稿，待审阅 · **最后更新**：2026-10-05

本章讲题目定下来之后，怎样为一个项目做计划：从最终要交出的成果倒推出要做哪些事，怎样定里程碑，怎样判断"做完了"，以及计划怎样随着结果更新。怎么选题见[选题](02_choosing_a_problem.md)；日常怎样推进、去风险、记日志、排日程见[推进研究](../2_during/01_making_progress.md)；论文怎么写见[写作](../3_after/01_writing.md)；怎样和导师沟通见[合作与导师](../4_throughout/01_collaboration_and_advisors.md)；项目材料怎么整理见[整理科研材料](../2_during/03_organizing_materials.md)。

**读完本章，你应该能：**

- 从"最终要证明什么"倒推出要做的实验、调查或分析；
- 在项目第一周写出一页项目简介；
- 事先写下"怎样算完成"；
- 用"拿到了什么证据"而不是"做了什么事"来定义里程碑；
- 把论文提纲当作项目进度表来用，并每周按主张回顾、更新计划。

---

## 1. 从终点倒推：先想清楚最后要说什么

**怎么做：**

大多数研究项目的终点是一篇论文（或学位论文的一章、一份报告）。计划从这个终点往回推 `[本项目分析]`：

```
研究问题 → 预期贡献 → 论文要提出的几条主张（claim）
        → 每条主张需要什么证据 → 产生这些证据的实验、调查、分析或证明
```

- **主张**是你希望读者读完后相信的结论，例如"方法 A 在条件 X 下比现有方法更准"或"这一群体的行为主要受因素 Y 影响"。
- 对每条主张问：**审稿人要看到什么，才会相信它？** 答案就是你要产生的证据（一张图、一张表、一个定理、一组访谈结果）。
- 实验和任务是从证据推出来的，不是先想到"可以做什么实验"再去找它能说明什么。

这里的"倒推"是从要说的内容倒推要做的工作；按时间从截止日期倒推、排日程，见[推进研究](../2_during/01_making_progress.md#7-规划长线项目和每周的时间)中"规划长线项目和每周的时间"一节。

**为什么：** Zhang 的第一条规则是：不要把写论文和研究本身分开。设计项目时就要心里装着最终的论文，在最初的设计文档里放一份论文提纲，用它来确定研究目标、实验的逻辑顺序和要准备的材料[^zhang2014ten-e8]。Noble 也建议把项目开始时写的说明当作论文引言的初稿[^noble2023ten-e1]。

**容易错在哪：**

- 一有想法就动手，可能追着一个没想清楚、其实站不住的想法跑很久[^noble2023ten-e2]。
- 只想到"要做哪些实验"，说不出"每个实验支撑哪条主张"。这样的实验做完，常常发现对论文没用。`[本项目分析]`

## 2. 第一周写一页项目简介

**怎么做：** 用一页纸回答下面这些问题。写不出来的地方，就是现在最该想清楚的地方。

| 栏目 | 写什么 | 依据 |
|---|---|---|
| 问题 | 要解决什么问题，范围到哪里为止 | [^noble2023ten-e3][^turingwaydesign-e6] |
| 意义 | 谁会因为这个问题被解决而受益，受益什么 | [^noble2023ten-e4] |
| 相关工作与空白 | 别人做到了哪里，还缺什么 | [^noble2023ten-e5] |
| 核心假设 | 用一句话说出核心想法 | [^noble2023ten-e6] |
| 预期贡献与主张 | 做成后能说的两三条结论 | [^zhang2014ten-e8] |
| 证据 | 每条主张靠什么证据、用什么指标判断成败 | [^noble2023ten-e8][^noble2023ten-e9] |
| 目标去处 | 打算投哪类期刊或会议，读者是谁 | `[本项目分析]` |
| 怎样算完成 | 见第 3 节 | `[本项目分析]` |

- 相关工作要在开头查。最糟的情况是做完整个项目，才发现别人早已发表了同样的工作[^noble2023ten-e5]。
- 写好后**给导师和信得过的同事看**，问他们：这个想法讲得通吗？针对的是一个重要且没解决的问题吗[^noble2023ten-e10]？
- 顺序不必死守，例如可以先确认有没有可用的数据，再写其他部分[^noble2023ten-e11]。

**容易错在哪：** 把简介写成详细的长篇计划。The Turing Way 收集的研究者项目设计遗憾中，有一条是"一开始计划太多，迟迟没有动手"[^turingwaydesign-e3]。一页就够，后面边做边改。

## 3. 事先写下"怎样算完成"

**怎么做：**

- "完成"的标准是：**每条核心主张都有了足够的证据**，而不是"没有事可做了"。研究永远有下一个实验可做。`[本项目分析]`
- 写成可以检查的形式，例如：
  - 计算类研究：新方法在三个数据集上都优于两种主流方法，且差异经过统计检验；
  - 访谈研究：访谈材料支持主题 X，并分析了不符合主题的反例；
  - 历史研究：档案证据覆盖 1950–1970 年，没有明显缺口；
  - 局限：已说明在条件 Z 下不成立。
- 完整性是论文的基石：研究的假设中重要的方面，都要有详细的支撑数据[^zhang2014ten-e12]。拿这条去对照你的清单。

**为什么：** The Turing Way 收集的研究者项目设计遗憾中，有一条是"没有一开始就争取更清晰的目标和成功标准"[^turingwaydesign-e1]。没有完成标准，项目要么无限延长，要么在证据不够时仓促投稿。`[本项目分析]`

**容易错在哪：** 把完成标准定成"结果要好到某个数字"。结果不由你决定；你能决定的是证据是否充分、主张是否和证据相称（见[写作](../3_after/01_writing.md)中"每个主张都要有相称的证据"一节）。`[本项目分析]`

## 4. 按"拿到的证据"定里程碑，分层规划

**怎么做：**

1. **分层。** 项目目标 → 里程碑 → 每个里程碑要回答的问题或支撑的主张 → 实验 → 具体任务。上层管方向，下层管本周做什么。`[本项目分析]`
2. **里程碑写成"拿到了什么证据"，不写"做了什么事"。** `[本项目分析]`

   | 不好的里程碑（活动） | 好的里程碑（证据） |
   |---|---|
   | 写完实验程序或问卷 | 预实验或小样本试做的结果表明核心假设站得住 |
   | 完成 20 次访谈 | 访谈材料足以回答研究问题 1，主题已基本饱和 |
   | 读完相关文献 | 写出一张对比表，说清已有工作缺什么 |

3. **按时间分层。** 学位论文按年，单个项目按学期或月，执行按周 `[本项目分析]`。The Turing Way 收集的遗憾中也有一条是没有设定短期和长期里程碑[^turingwaydesign-e2]。短期里程碑排得细，远期只写方向，因为研究的目标本身会演变[^turingwaydesign-e7]。日常的三层目标和日程安排见[推进研究](../2_during/01_making_progress.md#7-规划长线项目和每周的时间)中"规划长线项目和每周的时间"一节。
4. **先安排信息量最大的里程碑。** 先去验证最可能让项目失败的主张，而不是先做容易的部分[^steinhardt2018stochastic-e12][^steinhardt2018stochastic-e3]。

**为什么：** "写完实验程序"可以按期完成，但项目可能一点没有前进；"拿到初步证据"才真正降低了不确定性。`[本项目分析]`

> **不同的看法：要不要画甘特图？**
> - The Turing Way 的项目设计清单建议建立包含关键里程碑、产出和截止日期的时间线，并把甘特图、路线图、项目看板列为有用的工具[^turingwaydesign-e5]。
> - 同一份手册也指出，研究项目的特点是不确定、目标会演变[^turingwaydesign-e7]；按固定顺序推进的瀑布式管理方法结构僵硬、开始后难以调整，不太适合研究[^turingwaydesign-e8]。
>
> 实际操作中 `[本项目分析]`：甘特图适合标出**里程碑和外部截止日期**（投稿、答辩、经费报告），让你和导师看清大的时间关系；日常探索性工作不要排进甘特图，用每周回顾来决定下一步。

## 5. 把论文提纲当作项目看板

**怎么做：**

- 从第一周起就维护一份论文提纲。Zhang 建议设想最终会有哪些图和表，并按逻辑顺序排好[^zhang2014ten-e10]；落到提纲上，可以在每一节写下要说的主张，每条主张下面列出它需要的图、表或关键材料 `[本项目分析]`。
- 每张图表标一个状态：未开始 / 有初步结果 / 已定稿。还没有的图表，就是你的待办清单[^zhang2014ten-e11]。
- **在真正的截止日期前设一个内部截止日期。** Karpathy 的导师要求截稿前两周交一份至少 5 页、包含全部最终实验（数字可以不是最终的）的初稿，并按正式审稿的流程做内部评审[^karpathy2016survival-e8]。这是会议截稿的做法；投期刊时，可以对应地给自己定一个内部定稿日 `[本项目分析]`。

**为什么：** 设想中的图表和它们之间的逻辑，可以直接用来组织研究工作[^zhang2014ten-e11]。提前排出整篇论文，几乎总会暴露出几个必须补做的关键实验[^karpathy2016survival-e9]，越早发现越有时间补。

**容易错在哪：** 提纲写好就不再看。提纲要随结果更新，主张变了，图表清单也要跟着变[^zhang2014ten-e9]。

## 6. 每周按主张回顾，持续更新计划

这是本指南唯一的每周回顾，分证据和时间两部分；输入是[推进研究](../2_during/01_making_progress.md#4-记研究日志并定期回顾)中每一两周一次的研究日志总结。日志怎么记、时间怎么排，都在推进研究那一章讲，这里不再重复。

**怎么做：** 每周花半小时，对照项目简介和论文提纲回答 `[本项目分析]`：

**证据部分**

1. 这周学到了什么？
2. 哪些主张变得更有把握，哪些变弱了？
3. 还有哪些关键的不确定？
4. 什么在阻碍论文成形？
5. 下一个**最小的、最能减少关键不确定性**的实验是什么？（这是第 4 节"先做信息量最大的事"在周尺度上的应用[^steinhardt2018stochastic-e12]。）

**时间部分**（Nanda 建议的每周回顾问题[^nanda2025mindsets-e7][^nanda2025mindsets-e8]）

6. 最近什么最花时间？
7. 什么卡住了我？
8. 犯了什么错，怎样调整做法避免再犯？

回顾后，把变化写回项目简介和提纲，并在和导师见面时一起过一遍（见[合作与导师](../4_throughout/01_collaboration_and_advisors.md)）。

**为什么：**

- 研究中用写作重新审视项目，常常会导致调整研究、修改设计、收集新数据[^zhang2014ten-e9]。核心假设也可能改变，要定期检查它是否仍是驱动研究的核心想法[^noble2023ten-e7]。
- The Turing Way 收集的遗憾中还有一条：没有充分考虑需求在项目中会变化，而这在学术研究中很常见[^turingwaydesign-e4]。计划不更新，很快就和实际脱节。

**容易错在哪：** 只回顾"做了哪些事"或"时间花在哪"。时间部分是辅助，回顾的重心是**证据**：论文离完成标准还差什么。`[本项目分析]`

## 本章检查清单

- [ ] 我能写出研究问题 → 主张 → 证据 → 实验这条链，每个实验都对应至少一条主张。
- [ ] 我有一页项目简介，导师或同事看过并提了意见。
- [ ] 我写下了"怎样算完成"，标准是核心主张的证据是否充分。
- [ ] 我的里程碑写的是"拿到什么证据"，而不是"做完什么事"。
- [ ] 最先安排的是最可能让项目失败的那条主张。
- [ ] 我有一份论文提纲，列出了每条主张需要的图表及其状态。
- [ ] 我在真正的截止日期前设了内部截止日期。
- [ ] 我每周按主张回顾一次，并把变化写回简介和提纲。

## 常见错误

| 错误 | 为什么是问题 |
|---|---|
| 想到就做，不写下来 | 可能追着一个没想清楚的想法跑很久[^noble2023ten-e2] |
| 做完项目才查文献 | 可能发现别人早已发表同样的工作[^noble2023ten-e5] |
| 开头写几十页的详细计划 | 迟迟不动手；研究的目标本来就会变[^turingwaydesign-e3][^turingwaydesign-e7] |
| 没有完成标准 | 项目无限延长，或证据不够就仓促投稿[^turingwaydesign-e1] |
| 里程碑写成"写完某某程序"或"做完多少次访谈" | 按期完成了，项目却没有前进 `[本项目分析]` |
| 先做容易的部分 | 难的部分最后才暴露根本问题[^steinhardt2018stochastic-e12] |
| 截止日期当天才第一次排出整篇论文 | 来不及补做缺失的关键实验[^karpathy2016survival-e9] |
| 计划定下后不再更新 | 计划和实际脱节，失去指导作用[^turingwaydesign-e4] |

## 延伸阅读

- **Noble, "Ten simple rules for defining a computational biology project"**（2023）：写项目简介时读。两页，十条规则几乎都适用于其他学科。
- **Zhang, "Ten Simple Rules for Writing Research Papers"**（2014）：前四条讲怎样让论文提纲驱动研究。
- **The Turing Way, Guide for Project Design**：想系统了解项目设计时读，包含一份开题清单和研究者回顾的项目设计遗憾。
- **Karpathy, "A Survival Guide to a PhD"**：写论文一节讲了内部截止日期的做法。
