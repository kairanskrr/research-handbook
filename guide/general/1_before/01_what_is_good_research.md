# 什么是研究，什么是好的研究

> **状态**：初稿，待审阅 · **最后更新**：2026-10-05

本章讲两件事：研究到底在产出什么，以及怎样判断一项研究做得好。怎么挑一个值得做的题目，见[选题](../1_before/02_choosing_a_problem.md)；具体怎么设计研究、怎么写论文，见[研究设计与方法选择](../1_before/04_research_design.md)和[写作](../3_after/01_writing.md)。

**读完本章，你应该能：**

- 说清研究和"学习""做作业"的区别；
- 说出自己的工作属于哪一类贡献；
- 用四条标准检查一项研究：问题重要、证据可靠、声明诚实、别人能接着做；
- 识别"样子像研究、实质不是研究"的常见情况。

---

## 1. 先弄清研究在产出什么：新的、经过验证、能传给别人的知识

一句话：研究是为了**增加知识存量**而进行的创造性、系统性工作，也包括为已有知识设计新的应用[^oecd2015frascati-e1]。这个定义来自 OECD（经济合作与发展组织）的《弗拉斯卡蒂手册》（Frascati Manual），各国统计"什么算研究"都按它来，覆盖所有学科，包括人文社科和艺术。

按这本手册，一项活动要算研究，下面五条要**同时**满足[^oecd2015frascati-e2]：

| 标准 | 意思 | 对你的提醒 |
|---|---|---|
| 新颖 | 目标是得到新发现 | 先确认答案确实还没人知道。重复别人的结果并发现不一致，也算新[^oecd2015frascati-e3] |
| 有创造性 | 基于原创的、不显而易见的想法或假设 | 例行操作不算研究，哪怕工作量很大 |
| 结果不确定 | 开始时不知道会得到什么、要花多久[^oecd2015frascati-e4] | 失败是正常的。如果结果早就确定，那更像作业 |
| 系统 | 有计划地做，并记录过程和结果[^oecd2015frascati-e5] | 从第一天起就记研究记录 |
| 可转移、可复现 | 新知识要能传给别人、让别人复现；负面结果也算[^oecd2015frascati-e6] | 结果不能只留在你脑子里，否则就丢了[^oecd2015frascati-e7] |

其他资料的说法与此一致：研究产出新知识，知识落在某个具体的结果上[^shaw2002makes-e2]；一个问题值多少，可以看它能增加多少**可验证的**知识[^alon2009choose-e1]。

**和做作业有什么不同** `[本项目分析]`：作业的答案老师早就知道，你只需做对；研究的答案还没人知道，所以你不仅要得到答案，还要拿出证据，让别人相信它是对的。科学最初就是这样一种区分想法的方法：试一试管不管用，不管用就淘汰[^feynman1974cargo-e1]。

## 2. 弄清自己要做哪一类贡献

研究成果不只"提出新方法"一种。开题时先想清楚自己要交出什么，后面的工作才有方向。

**按目标分**，研究有三类[^oecd2015frascati-e8][^oecd2015frascati-e9]：

- **基础研究**：为了弄懂现象背后的道理，不以特定应用为目标；
- **应用研究**：同样为了获得新知识，但指向一个具体的实际目标；
- **试验发展**：利用已有知识，做出新产品、新流程，或改进已有的。

三者没有先后和高低之分，知识在它们之间双向流动[^oecd2015frascati-e10]。

**按问题和结果分。** Mary Shaw 分析软件工程研究时，归纳了研究问题和结果的类型[^shaw2002makes-e3][^shaw2002makes-e4]。去掉领域细节后 `[本项目分析]`，大致是：

| 你在问的问题 | 你交出的结果 |
|---|---|
| 怎样做到 X？有没有更好的做法？ | 一种方法或技术 |
| 怎样评估 X？怎样在 X 和 Y 之间选？ | 一种分析或评估方法、一次具体的比较 |
| 某个具体对象是什么样的？ | 对它的分析、测量或解答 |
| 一类对象有什么共同规律？ | 一个模型、一套分类 |
| X 究竟可不可能？ | 一个可行性证明或原型 |

换个角度看，最让人记住的成果大致有三种：改变人们看法的突破性结果、别人能反复使用的方法、对反复出现的问题的深刻洞见[^schulman2020opinionated-e1]。

**按确定程度分。** Shaw 转述 Brooks 的三层划分[^shaw2002makes-e5]：

- **确证的发现**：看是否真实、严谨；
- **观察**：如实报告实际现象，看是否有意思；
- **经验法则**：作者署名担保的概括，数据未必充分，看是否有用。

在还没有确证发现的领域，观察和经验法则也有价值，并为以后得出确证发现打基础[^shaw2002makes-e6]。所以新手不必觉得"只是观察"就拿不出手，但要**如实标明自己的结果属于哪一层**。

**怎么用**：开题时写下一句话："我要回答的问题是____；我会交出____（方法 / 模型 / 测量 / 解答 / 观察）；我会用____证明它成立。"问题、结果和验证方式要互相匹配[^shaw2002makes-e9]，这三点也正是一个领域判断研究好坏的依据[^shaw2002makes-e1]。

## 3. 做重要的问题

好研究的第一条，是问题本身值得做。

- 不做重要的问题，就不太可能做出重要的工作[^hamming1986you-e1]。
- "重要"不只看结果有多大，还要**有合理的攻克途径**。时间旅行意义重大，但没人知道从哪下手，所以不算重要问题[^hamming1986you-e2]。
- 聪明又勤奋的人做不出好研究，主要原因往往是做了不重要的问题[^schulman2020opinionated-e2]。
- 目标是发现有意思、重要、新的东西，而不是"写出一篇论文"；论文是自然的结果[^carlini2026best-e1]。

怎样找到并判断这样的问题，见[选题](../1_before/02_choosing_a_problem.md)。

> **不同的看法：好研究一定要"有用"吗？**
> - Zeller 转述 Hotz 的模型：好研究有三条互相独立的轴，即难不难、优不优雅（能否反复用于新问题）、有没有用；在任何一条上做得好就是好研究[^zeller2012good-e1][^zeller2012good-e2]。三条轴没有高低之分[^zeller2012good-e4]，而且很难兼得："难度、优雅、有用，三选二"[^zeller2012good-e3]。
> - Patterson 则把"解决有人关心的问题"放在选题的第一条[^patterson2001bad-e3]。
> - 《弗拉斯卡蒂手册》明确承认不以应用为目标的基础研究[^oecd2015frascati-e8]。Feynman 举过一个例子：一位宇宙学家担心说"没有应用"会拿不到经费，Feynman 认为编造应用是不诚实的，应当如实说明[^feynman1974cargo-e8]。
>
> 实际操作中：想清楚你的工作主要在哪条轴上有价值，**如实说出来**。不要为了显得"有用"而硬凑应用场景。

## 4. 用清楚、令人信服的证据支撑结果

光有结果不够。好研究还要有清楚、令人信服的证据，证明结果成立；证据应来自实际使用或系统分析，而不是说得好听的论证或精心挑选的例子[^shaw2002makes-e7]。只靠断言、不给证据的工作，很少被接受[^shaw2002makes-e8]。

**怎么做：**

- **先复现，再改条件。** 想在别人的结果上换个条件试试，先在你自己的条件下把原结果重复出来；否则你不知道差异是不是真的来自你改的那个因素[^feynman1974cargo-e10]。
- **每次只改一个因素，多次重复，控制混杂因素**[^patterson2001bad-e1][^carlini2026best-e2]。
- **替怀疑者提问。** 预见读者会对你的设置提出什么质疑，提前用实验回答[^carlini2026best-e2]。
- **对自己的假设既信又疑。** 相信到足以推进，怀疑到足以发现错误[^hamming1986you-e3]。

## 5. 只声明证据支持的东西：不要骗自己

Feynman 说，科学的第一原则是不要骗自己，而你自己是最容易被骗的人[^feynman1974cargo-e7]。很多研究形式上一切齐全，却缺了这一条，他称之为"货物崇拜科学"：跑道、塔台都搭好了，飞机就是不来[^feynman1974cargo-e2]。

**怎么做：**

- **报告可能让结论不成立的一切。** 包括其他可能的解释，以及你已经排除了哪些、怎么排除的[^feynman1974cargo-e3]。
- **把不符合的证据也写出来。** 提出理论时，与它不符的事实要和支持它的一起写[^feynman1974cargo-e4]。达尔文会把每条与自己观点相矛盾的证据记下来，因为不记就会忘[^hamming1986you-e4]。
- **给出让别人自己判断的全部信息**，而不是只给引向某个结论的信息[^feynman1974cargo-e5]。
- **结果不论正负都报告。** 只发表某一类结果，论证就会显得比实际更好[^feynman1974cargo-e9]；没有证实假设的负面结果，同样是研究成果[^oecd2015frascati-e6]。
- **连暗示也要诚实。** 每句话都属实、整体却给人错误印象，同样不行[^feynman1974cargo-e6]。

## 6. 让别人能在你的工作上继续

科学的本质是积累。做研究要让别人能在你的工作上继续往上搭[^hamming1986you-e5]。重大结果靠许多项目的证据慢慢积累，单篇论文提供的是一份增量[^shaw2002makes-e10]。

**怎么做：**

- **记录并公开足够的细节**，让别人能复现你的结果[^patterson2001bad-e2][^oecd2015frascati-e5]。
- **把具体问题当作一类问题来解**。Hamming 下决心不再孤立地解决一个问题，而是把它当作一类问题的代表[^hamming1986you-e6]。解法更通用，别人也更容易接着用。
- **把工作讲清楚、讲出去。** 别人都忙于自己的工作，做完了没人读，等于知识没有传出去[^hamming1986you-e7][^oecd2015frascati-e7]。

## 本章检查清单

- [ ] 我能说清楚：我要找的答案目前确实没人知道[^oecd2015frascati-e2]
- [ ] 我写下了"问题—结果—验证方式"，三者互相匹配[^shaw2002makes-e9]
- [ ] 我知道自己的结果属于确证的发现、观察还是经验法则，并会如实标明[^shaw2002makes-e5]
- [ ] 这个问题有合理的攻克途径，而不只是"意义重大"[^hamming1986you-e2]
- [ ] 我的证据来自系统的实验、分析或实际使用，而不只是举例或论证[^shaw2002makes-e7]
- [ ] 改条件之前，我先复现了原结果[^feynman1974cargo-e10]
- [ ] 我记下了所有与结论不符的证据，并会写进报告[^feynman1974cargo-e4]
- [ ] 无论结果正负，我都打算报告[^feynman1974cargo-e9]
- [ ] 我有过程和结果的记录，细节足够别人复现[^oecd2015frascati-e5][^patterson2001bad-e2]

## 常见错误

| 错误 | 为什么是问题 |
|---|---|
| 把"写出一篇论文"当成目标 | 目标应是发现新东西，论文只是结果[^carlini2026best-e1] |
| 做一个结果早已注定的题目 | 不满足"结果不确定"，更像作业而不是研究[^oecd2015frascati-e4] |
| 选一个意义重大但完全无从下手的题目 | 没有攻克途径的问题不算重要问题[^hamming1986you-e2] |
| 用几个精心挑选的例子当证据 | 例子和说理不是令人信服的证据[^shaw2002makes-e7] |
| 直接在别人的结果上改条件，不先复现 | 不知道差异是否真的来自你改的因素[^feynman1974cargo-e10] |
| 只报告支持结论的结果 | 论证会显得比实际更好，等于骗读者也骗自己[^feynman1974cargo-e9][^feynman1974cargo-e5] |
| 为了显得有用而编造应用场景 | 这是不诚实的[^feynman1974cargo-e8] |
| 结果只在自己脑子里或散落各处 | 不可转移、不可复现，知识会丢失[^oecd2015frascati-e7] |

## 延伸阅读

- **Feynman《Cargo Cult Science》**：讲科学诚信最好的一篇，十几分钟能读完，适合每个新手读一遍。
- **Hamming《You and Your Research》**：关于"做重要的工作"最常被引用的演讲。Erren 等人 2007 年在 PLoS Computational Biology 上把它归纳成十条规则，可以先读这个短版。
- **《弗拉斯卡蒂手册》第 2 章**：想弄清"什么算研究"的正式定义和五条标准，读第 2.2–2.4 节即可。
- **Shaw《What Makes Good Research in Software Engineering?》**：用"问题—结果—验证"三个维度刻画研究，虽然以软件工程为例，思路适用于大多数学科。
- **Zeller《What makes good research?》**：一页短文，讲好研究的三条轴，适合在怀疑"我的工作算不算好研究"时读。
