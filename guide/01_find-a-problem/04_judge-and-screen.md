# 判断和筛选

> 本章的道理适用于各学科，例子和具体做法以计算机为例。

> **这一章必须做的事** `[本项目分析]`
>
> 1. **对清单上每条快速问四件事。** 说得清吗？有下手的办法吗？被别的压过吗？适合你吗？每条只花几分钟，不在这里查重、想证据（[第 1 节](#1-快速初筛每条问四件事)）。
> 2. **看它适不适合你。** 你还想着它吗？你有没有优势？资源一眼看去够不够？导师帮得上吗（[第 2 节](#2-适合你吗兴趣能力资源导师方向)）？
> 3. **拿不准，就请导师打分。** 每条打 1–10 分，对分歧大的几条深入讨论（[第 3 节](#3-拿不准就请导师打分)）。
> 4. **留下两到四条，划掉的写原因。** 一句就够，比如"没有下手办法""被第 X 条压过""资源不够"（[第 3 节](#3-拿不准就请导师打分)）。
>
> **做到了就往下走：** 每条都过了一遍四问，留下两到四条，说得出为什么留、为什么划掉，至少和导师或一位懂行的人一起看过。下一步：[收敛成项目](05_converge.md)。

## 你现在在哪里

你有一份想法清单（见[生成候选问题](02_generate-problems.md)），其中几个已经动手试过（见[动手探索](03_explore.md)）。比如"评测集泄露"那条，你搜到了几份公开出现过的评测合约，写出了一个初步的假设；"误报太多"那条，你拿几份没有漏洞的合约试过，大模型确实报出不少"漏洞"；还有几条没来得及试。

清单上有十条左右，你不可能每条都深入做。该挑哪几个？

## 这一阶段要解决什么

对清单上的**很多个**想法，做一次**便宜的快筛**，留下两到四个，带进下一章。

它和下一章[收敛成项目](05_converge.md)分工不同 `[本项目分析]`：

| | 判断和筛选（本章） | 收敛成项目（下一章） |
|---|---|---|
| 对象 | 清单上的很多个想法 | 留下的两到四个，最后收敛到一个 |
| 每个花多少时间 | 几分钟 | 几天到几周 |
| 问什么 | 说得清吗？有下手的办法吗？被别的压过吗？适合你吗？ | 值不值得做？别人做过没有？拿什么让人信？做不做得出来？ |
| 产出 | 留下的候选，以及划掉的原因 | 一页项目简介，以及出口检查 |

## 1. 快速初筛：每条问四件事

这一步只花一两个小时。目的不是选出最终题目，而是把明显不值得深想的划掉 `[本项目分析]`。

**对每条想法，快速问四件事** `[本项目分析]`：

1. **能用一句话说清"不对劲的是什么"吗？** 说不清的，先留在清单里继续想，不进入这一轮。
2. **能看到一个下手的办法吗？** Hamming 说，让一个问题重要的，不是它的结果有多大，而是你有一个合理的攻克途径[^hamming1986you-e2]。连第一步怎么做都想不出的，先放下。
3. **它是不是被另一条全面压过？** 如果 A 在可行性和价值两方面都比 B 好，就可以划掉 B[^alon2009choose-e6]。粗看就行，不需要打分。
4. **它适合你吗？** 看兴趣、能力、资源和导师方向，见第 2 节。

动手探索过的想法，这四问答起来更有根据。没来得及试的，凭现有了解粗判就行；拿不准又看着有希望的，可以先回[动手探索](03_explore.md)试一下再筛 `[本项目分析]`。

**这一步不做的事。** 不在这里查清"别人做过没有"，不在这里想清"要什么证据"，也不细算数据和算力。那些是[收敛成项目](05_converge.md)要对两到四个候选认真做的事。初筛时对每条只花几分钟 `[本项目分析]`。

**写下来：** 对清单上每条想法，写下四问的简短回答。

## 2. 适合你吗：兴趣、能力、资源、导师方向

同一个想法，对别人是好题目，对你不一定。问四件事：

- **兴趣：你还想着它吗？** 问自己：如果世界上只有我一个人，我会做这些里的哪一个[^alon2009choose-e12]？几个月里反复回到你脑中的想法，是你真正感兴趣的好信号[^alon2009choose-e13]。留意分清两个声音：周围人在会议上、系里大声说"这个重要"，和你自己心里小声说"这个我觉得有意思"[^alon2009choose-e11]。不要扎堆追最热的问题[^huang2023decide-e1]。逼自己做不觉得兴奋的题目，即使理智上认为它更重要，效率也会低很多[^olah2021taste-e3]。
- **能力：你在这里有没有优势？** 一个问题要做多久，取决于做的人的技能和实验室的条件[^alon2009choose-e2]。弄清自己相对别人的独特优势[^huang2023decide-e1]。在一个没那么"重要"、但你很擅长的问题上，贡献可能比做一个你不擅长的问题更大[^carlini2026best-e11]。刚开始做研究时，选一个容易些的问题更好，能更快得到正反馈[^alon2009choose-e7]。
- **资源：数据、算力、时间大致够吗？** 这里只粗看，一眼就能看出做不了的就划掉，比如要从头训练一个大模型，而你只有一张显卡。细的可行性检查留给[收敛成项目](05_converge.md#5-你做得出来吗) `[本项目分析]`。
- **导师方向：导师帮得上你吗？** 研究早期高度依赖导师或成熟研究方向的指导，是正常的[^nanda2025taste-e9]。做有经验的人建议的想法也不丢人[^schulman2020opinionated-e4]。但导师的看法只是参考：导师通常有好的研究直觉，可你对自己这个具体问题的了解比他们多得多[^nanda2025mindsets-e15]。和导师方向差得很远的想法，先和导师谈清楚对方愿不愿意支持 `[本项目分析]`。

用"大模型与智能合约安全"举例 `[本项目分析]`：

| 想法 | 四问的结果 | 去留 |
|---|---|---|
| 现有大模型漏洞检测的评测结果被数据泄露高估了 | 说得清；下手办法清楚（查评测合约的来源，比较去掉前后的准确率）；探索时最兴奋；只需调用接口；导师做过评测 | 留 |
| 误报太多，开发者不愿意用 | 说得清；可以统计误报、访谈开发者；有兴趣，但没做过访谈，要学 | 留 |
| 换一种提示，检出率变化大吗 | 说得清；但和第一条比，价值更小、难度差不多，被压过 | 划掉 |
| 从头训练一个专门看合约的大模型 | 资源远远不够 | 划掉 |
| "大模型会改变合约安全" | 说不清不对劲的是什么 | 留在清单继续想 |

**写下来：** 对通过前三问的每条想法，各写一句兴趣、能力、资源、导师方向的判断。

## 3. 拿不准，就请导师打分

把清单给导师，请对方对每条打 1–10 分，对你们分歧大的几条深入讨论[^olah2021taste-e4]。这既是筛选，也是在练你判断问题好坏的能力。

这种能力常被叫作"研究品味"，大致就是挑选好问题的能力[^olah2021taste-e1]，主要从做研究的练习中来[^carlini2026best-e5]。怎么长期培养，见[有意识地培养研究品味](../08_throughout/mindset_and_growth.md#1-有意识地培养研究品味)。

**写下来：** 在想法清单上标出这一轮留下的两到四条，并对每条被划掉的写一句原因（"没有下手办法""被第 X 条压过""资源不够"等）。

## 关键判断

**留下几个才合适？** 可以这样判断 `[本项目分析]`：

| 情况 | 做法 |
|---|---|
| 留下两到四条 | 进入[收敛成项目](05_converge.md) |
| 留下五条以上 | 用"被压过"再比一轮，或者请导师打分 |
| 一条都不剩 | 清单太窄或太模糊，回到[生成候选问题](02_generate-problems.md)再找一轮 |
| 最有意思的那条和导师方向不合 | 先和导师谈，说清你探索到了什么；别悄悄把它改成自己不再兴奋的样子 |

## 常见错误

| 错误 | 为什么是问题 |
|---|---|
| 初筛时就把每条都想得很深 | 时间花在了终会被划掉的想法上；深入的检查留给下一章 `[本项目分析]` |
| 只看想法本身好不好，不看适不适合你 | 一个问题要做多久，取决于你的技能和条件[^alon2009choose-e2] |
| 追最热的方向 | 不要扎堆追最热的问题[^huang2023decide-e1]；不在最热的方向，反而更容易脱颖而出[^carlini2026best-e12] |
| 只按导师的口味挑 | 你对自己的具体问题了解得更多，可以有自己的判断[^nanda2025mindsets-e15] |
| 划掉的想法不写原因 | 以后回头看不出为什么放下，也没法从中学习 `[本项目分析]` |

## 产出物

- 初筛结果：留下的两到四条，以及每条被划掉的原因（第 1、3 节）
- 留下的每条各有一句"适合你吗"的判断（第 2 节）
- 如果请导师打过分，记下分数和分歧最大的几条讨论的结果

## 检查点

满足下面几条，可以进入下一步：

- [ ] 清单上每条想法都过了一遍四问
- [ ] 留下两到四条，说得出为什么留它们、为什么划掉其他的
- [ ] 留下的每条，都想过兴趣、能力、资源和导师方向
- [ ] 至少和导师或一位懂行的人一起看过筛选结果

## 回退信号

| 出现这种情况 | 回到哪里 |
|---|---|
| 筛完一条不剩 | [生成候选问题](02_generate-problems.md)，换一种来源再找 |
| 好几条都拿不准，四问答不上来 | [动手探索](03_explore.md)，先对它们做几次小尝试 |
| 对这个方向本身已经没有兴趣 | 和导师谈，考虑换方向；逼自己做不觉得兴奋的题目，效率会低很多[^olah2021taste-e3] |

## 下一步

带着留下的两到四个候选，进入[收敛成项目](05_converge.md)：把每个写成一句想证明的结论，深入检查值不值得做、别人做过没有、拿什么让人信、做不做得出来，最后收敛到一个，并做一次出口检查。

被否定的候选放回想法清单，写上原因。
