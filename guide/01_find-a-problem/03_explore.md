# 动手探索

> 本章的道理适用于各学科，例子和具体做法以计算机为例。本章引用的经验大多来自机器学习研究者。

> **这一章必须做的事**
>
> 1. **先认清你在探索。** 还写不出一个具体的假设，你就在探索阶段，目标只是弄懂问题，不必为没有假设焦虑（[第 1 节](#1-先认清你在探索还不是在检验)）。
> 2. **对最想做的两三条，各做一个小而快的尝试。** 最好一天之内看到结果，比如直接看一批真实的例子；先做信息最多的那一步（[第 2 节](#2-设计小而快的探索)）。
> 3. **边做边记探索笔记。** 试了什么、看到了什么、意外在哪、冒出什么新问题；没"成功"的也记（[第 3 节](#3-记探索笔记)）。
> 4. **给每个想法定一个时间上限。** 写出了具体假设，就往下走；学不到新东西了，就换做法或换想法，写下原因（[第 4 节](#4-什么时候停)）。
> 5. **别把看到的现象当结论。** 探索没有事先定标准，结果只是线索，要到第二部分再检验（[第 5 节](#5-探索和最小可跑版本不是一回事)）。
>
> **做到了就往下走：** 至少一个想法写出了具体假设，并说得出什么证据能判断它；放下的想法写了原因。下一步：[判断和筛选](04_judge-and-screen.md)。

## 你现在在哪里

你在[生成候选问题](02_generate-problems.md)里攒了一份想法清单。比如在"大模型与智能合约安全"这个方向，清单上有"现有大模型漏洞检测的高准确率，可能部分来自评测集泄露""误报太多，开发者不愿意用"等几条。

但这些想法还停在纸面上。你不知道评测集到底有没有泄露，也不知道大模型实际会在哪里出错。你可能担心：还没想清楚就动手，是不是太草率？

## 这一阶段要解决什么

用小而快的动手尝试，把纸面上的想法变成"我大概知道这里是怎么回事"。

这一步的目的是**获取信息、弄懂问题**，不是证明什么。所以它不求严谨，求快、求多看。具体要回答四个问题：

1. 我现在是在探索，还是已经能检验一个具体的假设？
2. 怎样设计小而快的探索？
3. 探索时记什么？
4. 什么时候停？

## 1. 先认清：你在探索，还不是在检验

**先问自己：我现在能不能写下一个具体的假设，并说出用什么证据判断它对不对？**

- **写不出来**：你在**探索阶段**。这时的目标只是获取信息：做小实验、看数据、跟着好奇心走，求快[^nanda2025process-e1]。
- **写得出来**：你可以进入**检验阶段**了。你已经足够了解这个问题，能写下具体的假设，也大致知道什么证据能说明它对不对[^nanda2025process-e5]。

新手在项目早期卡住，常常是因为以为自己已经在检验阶段，其实还在探索阶段[^nanda2025process-e2]。认清这一点，就不必因为暂时没有清晰的假设而焦虑。

**为什么现在就动手，而不是继续读、继续想。** 还没动手就想挑出完美的问题，是一个陷阱：判断问题好坏的能力，离不开亲手做[^olah2021taste-e9]。找想法找到一定程度后，多想一小时，不如先随便动手做点什么[^carlini2026best-e13]。

**阶段可以倒退。** 做到后面发现事情比想象中乱，退回检验甚至探索阶段，是正常的，不代表你搞砸了[^nanda2025process-e6]。在第二部分执行时写不出具体假设，也说明你该回到这一章。

**写下来：** 对清单上你最想做的两三个想法，各写一句：现在能不能写下具体假设？写不出来的，就是这一章要探索的对象。

## 2. 设计小而快的探索

**原则：每次探索都要便宜，最好一天之内看到结果。** 早期用一天之内能跑完的快速实验去试各种想法[^perez2024tips-e3]；先花一点时间看到初步迹象，远好于花几周做一个结论明确但又贵又慢的实验[^nanda2025mindsets-e11]。

**几种常用的做法：**

- **直接看一批真实的例子。** 比如想用一个数据集，可以先下载几千条，手工看一些，再算几个汇总统计，看它有没有你想要的性质[^steinhardt2018stochastic-e6]。
- **先想简化版本。** 问题太大无从下手时，先想它的简化版本，比如只看一类漏洞；简化版本常能提示原问题该怎么做、不该怎么做[^steinhardt2018stochastic-e8]。
- **先做信息最多的那一步。** 有几件事可以试时，按"单位时间内能带来多少信息"排序，从多到少做[^steinhardt2018stochastic-e4]。
- **问自己：如果这个方向注定不行，怎样最快发现？**[^nanda2025mindsets-e12]

**"不求严谨"指的是什么**：探索时不需要大样本，不需要事先定好判断标准，不需要统计检验，代码也不必写得漂亮。但要记下自己做了什么、看到了什么（第 3 节），因为探索得来的印象只是线索，不能直接当成结论。

**智能合约的例子**：清单上的几个想法里，你对"评测集泄露"最好奇。下面这些都是一两天内能做完的探索：

| 想弄懂的事 | 小而快的探索 |
|---|---|
| 大模型看合约时到底在说什么、错在哪 | 随手挑几十份合约交给大模型，读它的回答 |
| 评测集里的合约是不是早就公开了 | 从评测集抽几份合约，在公开代码平台上搜它们的关键代码片段 |
| 大模型是不是"记得"这些合约 | 只给它合约的前半段，看它能不能续写出后半段 |
| 误报多不多 | 拿几份已知没有漏洞的合约，看大模型报出多少"漏洞" |

做完这些，你可能发现：抽到的评测合约里，有好几份在公开代码里能搜到几乎一样的原文。这还不是结论，但它让你第一次能写出一个具体的假设（第 4 节）。

**写下来：** 对你要探索的每个想法，写出一个一两天内能做完的小尝试：想弄懂什么、具体做什么、大概要多久。

## 3. 记探索笔记

探索时的发现很零碎。不记下来，几天后就分不清哪个是哪次看到的。

**怎么记：**

- **边做边记。** 一边跑实验，一边开一份文档，结果出来就把图表、数字，以及自己的观察和体会加进去[^perez2024tips-e4]。每天的想法和实验都记进同一本笔记[^schulman2020opinionated-e16]。
- **另开一份亮点记录**，只收特别有意思的结果，方便发现它们之间的联系[^nanda2025process-e4]。
- **没"成功"的尝试也记。** 要紧的是你有没有在了解这个问题；只要在学，实验没"成功"也不算白做[^perez2024tips-e1]。

每条笔记可以写这几栏：

| 栏目 | 例子 |
|---|---|
| 日期、试了什么 | 10 月 3 日：从评测集抽 20 份合约，在公开代码平台搜关键片段 |
| 看到了什么 | 7 份能搜到几乎一样的代码 |
| 意外之处 | 搜到的大多是几年前上传的，早于模型的训练数据截止时间 |
| 冒出的新问题 | 别的评测集也这样吗？泄露的合约，模型答得是不是更准？ |
| 下一步 | 再抽一个评测集试试 |

探索笔记是第二部分研究日志的雏形。到了检验阶段，记录要更完整，见[整理科研材料](../08_throughout/organizing_materials.md#3-每个结果都要能追溯到它是怎么来的)。

**写下来：** 建好探索笔记和亮点记录。每做完一次小尝试，填一行上表。

## 4. 什么时候停

探索不是越久越好。有两种信号告诉你该停了。

**信号一：你写得出一个具体的假设，并知道什么证据能判断它。** 这正是进入检验阶段的标志[^nanda2025process-e5]。比如："公开评测集里有相当一部分合约，在模型训练之前就已公开；去掉这些合约后，大模型的检出率会明显下降。"你也知道要什么证据：泄露的合约占多少，去掉前后准确率差多少。到这一步，就带着这句话进入[判断和筛选](04_judge-and-screen.md)；如果你只剩这一个候选，而且已经和导师谈过，也可以直接进入[收敛成项目](05_converge.md)。

**信号二：单位时间里学不到新东西了。** 经常问自己："单位时间内，我得到的信息够不够？"最近没学到新东西，就换个做法[^nanda2025process-e3]。项目收益越来越少时，换项目完全可以[^perez2024tips-e2]。换有两种：

- **换做法**：同一个想法，换一种探索方式，比如从"读大模型的回答"换成"搜评测合约的来源"；
- **换想法**：换了几种做法都学不到新东西，就把这个想法放回清单，写上原因，去探索下一个。

**也别换得太勤。** 该放弃的方向要果断放弃，但要当心换的代价：总在换、哪个都没认真探索，什么也学不到[^nanda2025mindsets-e1]。有人陷在细节里出不来，要学会往前走；也有人一直等一个并不存在的完美机会，什么都不做[^nanda2025mindsets-e9]。

一个可操作的办法：给每个想法的探索定一个时间上限，比如一到两周。时间到了，用上面两个信号判断：写出了假设就往下走，学不到新东西就换，介于两者之间就和导师聊一次再定。

**写下来：** 给每个正在探索的想法写下时间上限。到期时写一句：写出了什么假设，或者为什么换。

## 5. 探索和"最小可跑版本"不是一回事

第二部分的[最小可跑版本](../02_do-the-project/05_pilot-and-derisk.md)也要做小实验，比如[先搭一个从头到尾能跑通的最小版本](../02_do-the-project/05_pilot-and-derisk.md#3-先搭一个从头到尾能跑通的最小版本)。两者看起来像，目的却不同：

| | 动手探索（本章） | 最小可跑版本（第二部分） |
|---|---|---|
| 目的 | 弄懂问题，找出值得检验的假设 | 检验已经写下的假设，排除设计里最大的风险 |
| 开始时手里有 | 一个模糊的想法 | 一句具体的主张、一张空的结果表 |
| 事先定标准吗 | 不用，跟着好奇心走 | 要，事先写好[什么结果算继续、调整、停](../02_do-the-project/05_pilot-and-derisk.md#5-事先写好什么结果算继续调整停) |
| 记录 | 探索笔记，记下看到的和想到的 | 开始正式留记录：每个结果都能追溯到代码、数据和参数 |
| 结果怎么用 | 只当线索，帮你写出假设 | 决定设计要不要改 |

最常见的混淆，是把探索时看到的几个例子，当成已经检验过的结论。探索里冒出的猜想，要到第二部分用事先定好的办法再检验一次。

**写下来：** 回头看你的探索笔记，标出哪些只是"看到的现象"，哪些已经接近"可以检验的假设"。

## 关键判断

**还要再探索，还是可以往下走？** 可以这样判断：

| 情况 | 做法 |
|---|---|
| 写得出具体假设，也知道什么证据能判断它 | 进入[判断和筛选](04_judge-and-screen.md) |
| 每次尝试都有新发现，但还写不出假设 | 继续探索，留意时间上限 |
| 换了几种做法都学不到新东西 | 换下一个想法；清单上的都试过了，回到[生成候选问题](02_generate-problems.md) |
| 发现想法的前提不成立（比如大模型在这些评测集上本来就答不准，谈不上被高估） | 这也是收获：放回清单写上原因，或者把这个发现改写成新想法 |

## 常见错误

| 错误 | 为什么是问题 |
|---|---|
| 一直读、一直想，迟迟不动手 | 判断问题好坏的能力离不开亲手做[^olah2021taste-e9] |
| 一开始就做又大又严谨的实验 | 几周后才看到结果；探索要的是快速看到初步迹象[^nanda2025mindsets-e11] |
| 以为自己该有明确假设了，其实还在探索 | 会卡住，不知道下一步做什么[^nanda2025process-e2] |
| 探索时不记笔记 | 几天后就说不清看到过什么 |
| 总在换想法，哪个都没认真试 | 什么也学不到[^nanda2025mindsets-e1] |
| 把探索看到的现象当成结论 | 探索没有事先定标准，结果只是线索 |

## 产出物

- 探索笔记和亮点记录（第 3 节）
- 每个探索过的想法的去向：写出的具体假设，或者放下的原因（第 4 节）
- 至少一句写得下的具体假设，以及你认为什么证据能判断它

## 检查点

满足下面几条，可以进入下一步：

- [ ] 清单上最想做的几个想法，各做过至少一次小而快的尝试
- [ ] 每次尝试都记进了探索笔记
- [ ] 至少一个想法写出了具体假设，并说得出什么证据能判断它
- [ ] 放下的想法写了原因，放回了想法清单
- [ ] 分得清哪些是探索中看到的现象，哪些还需要检验

## 回退信号

| 出现这种情况 | 回到哪里 |
|---|---|
| 想不出任何能动手试的小尝试 | 想法太模糊，回到[生成候选问题](02_generate-problems.md)把它说具体 |
| 清单上的想法都探索过，都学不到新东西 | 回到[生成候选问题](02_generate-problems.md)，换一种来源再找 |
| 看不懂探索的结果（比如判断不了大模型的回答对不对） | 领域知识还不够，回到[进入领域、探索文献](01_enter-a-field.md) |

## 下一步

带着探索笔记和写出的假设，进入[判断和筛选](04_judge-and-screen.md)：把探索过和没探索过的想法放在一起，快速筛出两到四个，带进[收敛成项目](05_converge.md)。
