# 怎么做好科研：整理内容

这里是我们从[原始资料](../sources/README.md)中整理出来的内容，用中文写给科研新手：读完能明白怎么做好科研，并能照着完成实际的研究工作；做研究时遇到常见问题，也能在这里找到建议。

## 三种读法

| 你的情况 | 从哪里读 |
|---|---|
| 第一次做科研，想知道一个课题从头到尾怎么做 | [通用篇](general/README.md)：先读总览，再按阶段往下读 |
| 正处在某个阶段（刚开题、在做实验、准备投稿） | [通用篇](general/README.md)中对应的阶段 |
| 遇到了具体问题（实验做不出来、被拒稿、导师没空……） | [常见问题速查](faq.md) |
| 要做某个领域的研究，或要用某种研究方法 | [领域篇](07_fields/README.md)，以及领域下的研究类型文档 |

## 内容的组织

```
general/          通用篇：所有学科共通的经验，按研究阶段分组
  00_workflow.md    总览：一个课题从头到尾怎么做
  1_before/         开始之前：想清楚做什么
  2_during/         进行中：把研究做扎实
  3_after/          收尾与发表：讲清楚、送出去
  4_throughout/     贯穿全程：合作、诚信、心态
fields/           领域篇：按 OECD 学科分类，每个领域下有研究类型文档
faq.md            常见问题速查：按症状列出，链接到具体段落
```

大致的分工是：**原则写进通用篇，具体做法写进研究类型，惯例写进领域篇。** 各阶段的名称在不同研究中基本相同（选题、了解已有工作、设计、产生证据、分析、写作、发表），共用的原则也很多，例如结论不超出证据、诚实披露局限；但同一个阶段的具体做法随研究方法而变，例如"文献调研"在一般研究中是背景工作，在系统综述中则是研究方法本身。ACM SIGSOFT Empirical Standards（美国计算机协会软件工程分会制定的一套实证研究标准）也认为不存在通用的质量标准，每项研究应按其方法的标准评判。`[本项目分析]`

## 怎么看出处

每条结论都用脚注标出依据。点开脚注可以看到出自哪份资料、原文在哪里、原文怎么说（见[证据摘录](../sources/notes/README.md)）。没有文献依据、属于我们自己的分析，标注 `[本项目分析]`；不确定的内容标注 `[待确认]`。不同资料说法不一致时，会并列写出各自的做法和理由。
