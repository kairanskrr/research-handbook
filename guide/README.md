## 为什么分成套路、方法、学科三层

同一个阶段（比如读文献、设计研究），各种研究要回答的问题大体相同，但具体做法随研究方法变。例如"读文献"在一般研究里是背景工作，在系统综述里就是研究方法本身。所以两部分主干只讲每个阶段要想清楚什么；具体怎么做，放进研究套路和研究类型；某个学科特有的要求，放进学科篇。

这样分也和"按方法评判研究"的做法一致：软件工程的一套实证研究标准认为，没有适用于所有研究的质量标准，每项研究都应按适合它的方法的标准来评价[^ralph2020empirical-e24]。为什么要分清套路，见[核心术语](00_start-here/key-concepts.md#研究套路)。

## 怎么看出处

每条有资料依据的话都用脚注标出依据。点开脚注可以看到出自哪份资料、原文在哪里、原文怎么说（见[证据摘录](../sources/notes/README.md)）。没有脚注的话，是本手册自己的综合和建议。不同资料说法不一致、而且会影响你怎么做时，会并列写出各自的做法和理由。详细说明见[怎么用这本手册](00_start-here/how-to-use.md#怎么看出处)。

[^ralph2020empirical-e24]: ACM SIGSOFT 实证研究标准，General Standard，General Quality Criteria。[证据](../sources/notes/ralph2020empirical.md#e24)
