# 计算机特有的研究实践

这里放五种主要在计算机（尤其软件工程）里使用的研究实践。它们讲的是这个学科社区里具体怎么做、审稿人具体查什么，例如怎样选基准、怎样从 GitHub 挖数据、怎样准备制品评估。

| 实践 | 一句话 | 通用部分在哪 |
|---|---|---|
| [工程研究](engineering_research.md) | 提出新的方法、工具或系统，并用评估证明它更好 | [构建改进](../../../05_research-strategies/build_improve.md) |
| [优化研究](optimization_study.md) | 把问题写成"在很多候选解中找最好的"，用搜索算法求解，再用重复实验比较 | [构建改进](../../../05_research-strategies/build_improve.md)、[比较评估](../../../05_research-strategies/compare_evaluate.md) |
| [基准评测](benchmarking.md) | 用一套标准的工作负载和自动化、可重复的流程，比较系统、工具或模型 | [比较评估](../../../05_research-strategies/compare_evaluate.md)、[测量](../../../05_research-strategies/measure.md) |
| [仓库挖掘](repository_mining.md) | 从代码仓库、缺陷库、问答网站中大规模抽取数据，研究软件是怎样开发出来的 | [观察描述](../../../05_research-strategies/observe_describe.md) |
| [理论研究](theoretical_research.md) | 以定理和证明为成果，包括复杂度分析和形式化验证 | [证明](../../../05_research-strategies/prove.md) |

**为什么放在计算机篇** `[本项目分析]`：本手册把具体做法分两处放。两个及以上学科都用的方法（问卷、访谈、对照实验、综述等），放在 `06_methods/`；只有一个学科使用的实践，放在该学科的 `practices/` 下。两类都在[研究类型](../../../06_methods/README.md)目录里列出。上面五种的具体做法（基线和基准的选法、git 数据的陷阱、制品徽章、机器检查的证明等）主要出自计算机的资料，所以放在这里。

**它们和套路页的分工** `[本项目分析]`：这类研究产生什么知识、一般要什么证据、为什么要和强基线比，写在上表第三列的套路页里，各学科通用；这里的各篇只写计算机里的具体做法，通用部分用链接指过去。计算机常用哪些套路、各看什么证据，见[计算机学科概况](../README.md#常用套路与证据标准)。

其他学科也用的方法（定量仿真、数据科学、复现研究等），计算机篇也会用到，列在[计算机学科概况](../README.md#研究类型)末尾。
